# ストレージ改修 実装方針(Gemini)
```
承知いたしました。 詳細設計書に基づき、ストレージ改修の実装方針を詳細に説明します。

ストレージ改修 実装方針 詳細説明
この改修の核心は、これまでCloudflare R2に直接ファイルを読み書きしていた処理を、Durable Objects (DO) を介して行うように変更することです。これにより、特に書き込み処理のレイテンシを大幅に改善し、ユーザー体験を向上させることを目指します。

実装は大きく分けて以下の3つのステップで進めます。

Durable Objectsクラスの実装:
スレッドのデータを管理する ThreadDO
板のスレッド一覧を管理する BoardDO
書き込み処理 (bbs.cgi.js) の改修:
R2への直接書き込みを、DOのメソッド呼び出しに置き換える。
読み込み処理 (main.js) の改修:
R2からの直接読み込みを、DOのメソッド呼び出しに置き換える。
以下に、それぞれの詳細な方針を説明します。

1. Durable Objectsクラスの実装
まず、データの格納と操作の責務を持つ2つのDurable Objectクラスを新たに作成します。

1.1. スレッドDO (ThreadDO)
1つのスレッドに対して1つのThreadDOインスタンスが対応します。DOのIDにはスレッドキー（例: 1719815493）を使用します。

責務
スレッドのレスデータ (dat) と投稿者ログ (log) を永続的に保持・管理する。
新しいレスの追加、既存レスの削除（あぼーん化）といった操作を提供する。
外部（Worker）からの要求に応じて、datやlogのデータを提供する。
永続化するデータ (Storage API)
title: (文字列) スレッドタイトル。
settings: (文字列) スレ設定 (NAME=VALUE<>...)。
resCount: (数値) 現在のレス数。
dat: (文字列) 2ch互換のdat形式データ。1レスごとに改行。
log: (文字列) 投稿者ログデータ。1レスごとに改行。
lastModified: (数値) 最終更新時刻のUnixタイムスタンプ。
提供するメソッド (インターフェース)
getDat(): dat形式の全スレッドデータを文字列として返します。
getLog(): log形式の全投稿者ログを文字列として返します。
getSummary(): スレッドの要約情報（タイトル、レス数、最終更新時刻など）を返します。
addRes(resData): 新しいレスを追加します。
引数: レス番号、名前、本文、ID、投稿者情報などを含むオブジェクト。
内部処理:
引数のresDataからdat形式とlog形式の行データを生成します。
state.storage.get()で現在のdatとlogを取得し、新しい行を追記します。
レス数 (resCount) をインクリメントし、最終更新時刻 (lastModified) を更新します。
state.storage.put()で更新したデータを永続化します。DOのトランザクション機構により、複数の書き込みはアトミックに（一体として）処理されます。
deleteRes(resNum): 指定されたレス番号をあぼーん化します。
内部処理:
datデータを取得し、指定されたレス番号の行をあぼーん<>...という文字列に置換します。
更新したdatデータを永続化します。投稿者ログ(log)は変更しません。
1.2. 板DO (BoardDO)
1つの掲示板（板）に対して1つのBoardDOインスタンスが対応します。DOのIDには板のディレクトリ名（例: livejupiter）を使用します。

責務
板のスレッド一覧 (subject.txt相当) を永続的に保持・管理する。
スレッドの追加（スレ立て）、更新（レス投稿によるage）、削除（dat落ち）をスレッド一覧に反映する。
永続化するデータ (Storage API)
subjectList: (配列) 各スレッドの情報をオブジェクトとして保持する配列。
例: [{ key: "171...", title: "...", resnum: 10, ... }, ...]
lastModified: (数値) 最終更新時刻のUnixタイムスタンプ。
提供するメソッド (インターフェース)
getSubject(format): subject.txt形式の文字列を返します。
引数: v1 (2ch互換形式) または v2 (独自形式) を指定。
内部処理: subjectList配列を元に、指定されたフォーマットの文字列を生成して返します。
updateThread(threadData): スレッド一覧を更新します。スレ立て・レス投稿（age）時に呼び出されます。
引数: スレッドキー、タイトル、レス数などのスレッド情報を含むオブジェクト。
内部処理:
subjectList内から同じスレッドキーを持つ要素を探します。
存在すれば、その要素を削除します。
引数のthreadDataをsubjectListの先頭に追加します。
板設定で定められた最大スレッド数を超えるなど、古いスレッドをsubjectListの末尾から削除します。
lastModifiedを更新し、subjectListを永続化します。
2. 書き込み処理 (bbs.cgi.js) の改修
bbs.cgi.jsは、R2のファイルを直接操作する代わりに、上記で定義したDOのメソッドを呼び出すように変更します。

スレッド書き込み (updateThreadFile関数):

env.THREAD_DO.get(id)で、スレッドキーをIDとするThreadDOのスタブを取得します。
stub.addRes(resData)を呼び出し、レスの追加をDOに依頼します。
これまでの「R2からファイルを読み込み→追記→ETag付きで書き戻し→競合時はリトライ」という複雑な処理は、この1行のメソッド呼び出しに置き換わります。競合制御はDOが内部で行うため、Worker側で考慮する必要はなくなります。
スレッド一覧書き込み (suretateTotalCheckAndUpdateSubject関数):

sage判定を行い、age対象の場合のみ処理を続行します。
env.BOARD_DO.get(id)で、板ディレクトリ名をIDとするBoardDOのスタubを取得します。
stub.updateThread(threadData)を呼び出し、スレッド一覧の更新をDOに依頼します。
ここでも、R2のファイルI/Oと競合制御のロジックが、1行のメソッド呼び出しに置き換わります。
3. 読み込み処理 (main.js) の改修
main.jsも同様に、R2から直接ファイルを読み込む代わりに、DOのメソッドを呼び出します。

スレッド読み込み (.dat):

env.THREAD_DO.get(id)でThreadDOのスタブを取得します。
stub.getDat()を呼び出し、dat形式の文字列を取得します。
取得した文字列をクライアントに返します。これまでの「ファイル全体を読み込んでからパースする」処理が不要になり、DOから取得したデータをそのまま返すだけでよくなります。
スレッド一覧読み込み (subject.txt):

env.BOARD_DO.get(id)でBoardDOのスタブを取得します。
stub.getSubject(format)を呼び出し、要求されたフォーマットのsubject.txt形式文字列を取得します。
取得した文字列をクライアントに返します。
以上の改修により、データ操作のロジックは各DOクラスに集約され、Worker (bbs.cgi.js, main.js) はDOを呼び出すだけのシンプルな責務になります。これにより、コードの見通しが良くなると同時に、Durable Objectsの特性を活かした高速なデータアクセスが実現されます。
```

これまでの「R2からファイルを読み込み→追記→ETag付きで書き戻し→競合時はリトライ」という複雑な処理は、この1行のメソッド呼び出しに置き換わります。競合制御はDOが内部で行うため、Worker側で考慮する必要はなくなります。
スレッド一覧書き込み (suretateTotalCheckAndUpdateSubject関数):

1. 投稿が`sage`かどうかを判定します。
2. `env.BOARD_DO.get(id)`で、板ディレクトリ名をIDとする`Board`のスタブを取得します。
3. `stub.updateThread(threadData, isSage)`を呼び出し、`sage`フラグを渡してスレッド一覧の更新をDOに依頼します。
ここでも、R2のファイルI/Oと競合制御のロジックが、1行のメソッド呼び出しに置き換わります。
3. 読み込み処理 (main.js) の改修
main.jsも同様に、R2から直接ファイルを読み込む代わりに、DOのメソッドを呼び出します。

スレッド読み込み (.dat):

env.THREAD_DO.get(id)でThreadのスタブを取得します。
stub.getDat()を呼び出し、dat形式の文字列を取得します。
取得した文字列をクライアントに返します。この際、main.jsが従来通りShift_JISへのエンコード変換や、Rangeヘッダに応じた差分取得の処理を担当します。 DOは純粋なUTF-8文字列を返すことに専念するため、既存の出力周りの機能への影響を最小限に抑えます。
スレッド一覧読み込み (subject.txt):

env.BOARD_DO.get(id)でBoardのスタブを取得します。
stub.getSubject()を呼び出し、subject.txt形式の文字列を取得します。
取得した文字列をクライアントに返します。ここでも、main.jsがShift_JISへのエンコード変換を担当します。

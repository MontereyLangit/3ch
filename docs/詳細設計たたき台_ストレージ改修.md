# 板・スレ ストレージ改修

## 機能概要
現状 R2（中央オブジェクトストレージ）へ板やスレのデータを直接読み書きしているため、書き込みレイテンシが大きくなっている。特に書き込み速度が著しく遅く、ユーザーの不満へとつながっている。  
板やスレのデータ保存先を、エッジで分散して動作するCloudflare Durable Objectsにすることで、特に書き込み速度の改善を図る。
NinjaAccount(忍法帖アカウント)関連もDO使用だが、今回は実装はなし

## 現行実装
### スレッド読み込み(dat・ログ)
```main.js
key:${bbs}/thread/${key.slice(0,4)}/${key}.cgiでR2から取得
タイトル\nスレ設定(NAME=VALUE<>NAME2=VALUE2)\n1レス目(0:num<>1:name<>2:sikibetsuId<>3:time<>4:id<>5:MESSAGE<>6:HOST999)\n2レスめ...\n
というように格納されている。

HOST999は投稿者ログ。
```
### スレッド書き込み(dat・ログ)
```bbs.cgi.js
bbs_entry() 内の updateThreadFile() で実行。
1. getThreadDataAndThreadSettings() でR2からスレッドファイル(.cgi)を読み込み、ETagを取得。
2. 新しいレスの内容を文字列として追記。
0:num<>1:name<>2:sikibetsuId<>3:time<>4:id<>5:MESSAGE<>6:HOST999
3. R2に onlyIf: { etagMatches: ... } を付けて書き戻すことで、競合（書き込み中に別のレスが投稿されること）を検知。
4. 競合した場合は、ファイルを再度読み込んでリトライする。
```

### 板のスレッド読み込み(subject)
```main.js
key:${bbs}/subject.txt でR2から取得。
1行目: 最終更新時刻(unixtime)
2行目以降: {key}.dat<>{title} ({resnum})\n
という形式で格納されている。
```
### 板のスレッド書き込み(subject)
```bbs.cgi.js
bbs_entry() 内の suretateTotalCheckAndUpdateSubject() で実行。
1. getSubject() でR2からsubject.txtを読み込み、ETagを取得。 
2. sageでない投稿の場合、subject.txtのメモリ上の内容を更新。

投稿されたスレッドの行を先頭に移動（or 新規追加）し、最終更新時刻を更新。
古いスレッドや規定数を超えたスレッドは削除。
3. R2に onlyIf: { etagMatches: ... } を付けて書き戻す。競合した場合は書き込みを諦め、sage扱いとする（エラーにはしない）。 
```

## 実装方針
### スレッドDO
スレDOでは2ch型掲示板のdat形式(key:`dat`)とログ(key:`log`で、各レスごとに`{レス番号}<>{datの投稿日時部分}<>{本文先頭一部}<>{投稿者ログ}\n`という感じで)に分割。  
書き込み時は両方記録。読み込み時は、必要な方を取る感じで。  
この改修によりdatの出力は取得した`dat`データをそのまま出力するだけでよくなります。  
レス削除時はdatの方のみを物理削除(該当行を`あぼーん<>あぼーん<>あぼーん<>あぼーん<>あぼーん\n`)すること。  
LastModifiedなどは最新レスを解析することにより取得してください。

### 板DO
板DOでは2ch型掲示板のsubject.txt形式(key:`subjectList`)を持つ。  
スレ立て規制用データを持つことも考えたが、subjectList(`{threadKey}.dat<>{title} [{posterInfo}] [{posterId}★]\n`)のposterInfoやposterIdを規制に利用できるため、持たなくてよい  
一方、通常の板内連投規制用のデータはkey:`timecheck`に持つ。  
板設定のtimecount件の最新投稿分投稿者ログを持っておき、板・スレ設定timeclose件自身の投稿があれば書き込み拒否（連投規制）する。※現時点では2ch互換で、IPをハッシュ化して記録。機械的に減らしていくのでレス情報は不要。すなわち次のような形式でよい:`{一番最新レスのIPのハッシュ}\n{2番め最新レスのIPハッシュ}\n...`という感じで  
ただし、subjectListの規制関係やtimecheck関連は今回の改修では実装しません。

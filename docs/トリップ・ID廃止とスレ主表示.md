# トリップ・ID の廃止と、`!id`・スレ主表示の追加

2026-11-02、利用者の指示による仕様変更。**状態: 実装済み（認証は未実装。認証ブランチのマージ後に有効になる部分あり）。**
本ブランチは認証機能（[auth-phoebe-rate-limit-design.md](https://github.com/MontereyLangit/ch3s/blob/claude/auth-phoebe-ratelimit-design-df5utn/docs/auth-phoebe-rate-limit-design.md)、別ブランチで設計中）の実装後にマージする前提。

## 1. 指示の要約

- トリップ機能を廃止する。代替の本人証明として、名前欄の `!id`（Web 版はフォームのユーザー名表示チェックボックス）で `(@ユーザーID)` を出す。
  クライアント ID 方式は自動で設定された ID、ID/Password 方式と Google OAuth 方式は登録したユーザー ID を出す。
- スレ主の証明として、スレ立て時の IP・識別子・ユーザー ID のどれかと一致したら名前欄末尾に ` (主)` を付ける。
  名前欄に `!no` があれば付けない（`!no` は書き込み時に除去する）。板設定かスレ設定の `BBS_DISABLE_NUSI` が `checked` なら付けない。
- 従来の ID（日付欄の `ID:xxxxxxxx`）を廃止する。IP ベースで識別子として弱いため。今後は名前欄の識別子だけでユーザーを識別する（ある程度の被りは許容）。

## 2. 仕様

### 2.1 トリップの廃止

- 名前欄の `#` 以降（従来トリップキーとして切り出していた部分。判定の正規表現は従来どおり）は**捨てる**。表示も保存もしない。
  トリップを付けるつもりで書いた利用者のキーが名前として公開されるのを防ぐため。
- `◆→◇`・`★→☆`・`＃→#` の置換は残す（過去ログのトリップ・キャップの偽装防止と、全角 `＃` のキーも捨てるため）。
- トリップキー長の上限エラー（1023 バイト）は廃止。
- 依存の削減: npm `unix-crypt-td-js`、`bbs/hash/UnixCrypt.scala`・`Hex.scala`、golden `crypt.json`・`crypt-bytes.json` を削除。
  `@noble/hashes`（MD5）はキャップ・PON・識別子で使うため当時は残したが、2026-11-09 に MD5 ごと廃止し SHA-256 に置き換えた（docs/v6s実装メモ.md §3.3）。

### 2.2 ID の廃止

- dat の日付欄は `2026/11/02(月) 12:34:56` のように日付だけになる（従来の ` ID:xxxxxxxx`・`ID:???`・`発信元:IP`・Lv 付加 `10` を出さない。末尾の空白も付けない）。
- スレ立て時に dat 第 5 フィールドのスレタイへ付けていた ` [ID★]` は付けない。
- `BBS_ID`・`BBS_ID_LV` は読まない（既定の `SETTING.TXT` からも削除）。`BBS_ID_GROUP`・`BBS_ID_RESET` は識別子の計算に使うので残す。
- R2 の過去ログ目次 `thread/xxxx/subject.txt` の ID 欄は、6 フィールドの形式を保つため空文字を書く。

### 2.3 `!id`（ユーザー ID の表示）

- 名前欄の `!id`（直後が英数字・`_` でないもの。`!idol` などは対象外）を全て取り除く。取り除いたときは名前の前後の空白も落とす（`名前 !id` が `名前` になる。名前が空になれば `BBS_NONAME_NAME`）。フォーム項目 `showid` が空でなければ `!id` と同じ扱い（Web 版のチェックボックス用）。
- 投稿者が認証済なら、名前の直後（識別子の前）に ` </b>(@ユーザーID)<b>` を付ける。ユーザー ID は HTML エスケープする。
- 未認証・キャップ投稿では取り除くだけで付けない。
- `BBS_NAME_COUNT` の検査は付ける前の名前で行う。
- 認証主体は `domain/posting/PostingUser`（`accountKey`: 移行しても変わらない内部 ID、`displayId`: 表示するユーザー ID）で受け取る。
  解決関数は `handler/PostingUserResolver`（型 `Resolver`）で、現時点の `PostingUserResolver.unresolved` は常に未認証を返す。
  `PostingHandler.entry` の第 3 引数で差し替えられる。**認証ブランチでここを Cookie / 専ブラ認証キーからの解決に差し替える。**
  表示 ID を方式ごとに選ぶ（クライアント ID は自動 ID、ID/Password・Google は登録 ID）のは認証側の責務とする。

### 2.4 スレ主表示 ` (主)`

- スレ立て時に Thread DO の新キー `owner` へ次を保存する（キャップのスレ立てでは保存しない）。

  | 項目 | 値 |
  | --- | --- |
  | `ip` | `SHA-256(keyIp + ":" + saltHash)`。`keyIp` は IPv4 はそのまま、IPv6 は展開した先頭 4 ブロック（/64） |
  | `shikibetsu` | そのレスの識別子（名前欄の `(…)` の中身）。空なら空 |
  | `account` | 認証済なら `SHA-256(accountKey + ":" + saltHash)`、未認証は空 |

- 返信（>>2 以降）で、保存した値と投稿者の値のうち**空でない項目が 1 つでも一致**したら、名前欄の末尾（識別子の後）に ` (主)` を付ける。
- 付けない条件: 名前欄に `!no`（直後が英数字・`_` でないもの）がある / 板の `SETTING.TXT` かスレ設定の `BBS_DISABLE_NUSI` が `checked` /
  キャップ投稿 / `owner` の無いスレ（本変更より前に立ったスレ、キャップが立てたスレ）/ >>1 自身。
- `!no` は付ける・付けないに関わらず常に取り除く。
- スレ移動（管理画面の move）では `owner` も移動先へ引き継ぐ。
- 識別子は `BBS_ID_RESET`（既定 1 日）ごとに変わるので、識別子での一致は同じ期間内に限られる。IP とユーザー ID はその制約がない。
- キャップを除くのは、キャップ所持者が名無しで書いたレスとキャップのスレを IP で結びつけて晒さないため。

### 2.5 名前欄の並び

```
名前 </b>(@ユーザーID)<b> </b>(識別子)<b> (主)
```

キャップは従来どおり `名前＠ハンドル ★ </b>(★)<b>`（`!id` も ` (主)` も付けない）。

## 3. 不変条件（AGENTS.md 3.4）への影響

| 項目 | 影響 |
| --- | --- |
| dat 構造 | `<>` 5 フィールドと本文前後の空白は不変。日付欄から ID が消え、名前欄に `(@id)`・` (主)` が加わる |
| ID / トリップの値 | 廃止。既存の dat に書かれた ID・トリップは本文データとしてそのまま残る |
| 識別子・キャップの値 | 不変 |
| ストレージ | Thread DO に `owner` キーを追加（既存キーの形式は不変）。R2 目次の ID 欄は空文字 |
| 専ブラ | ID 抽出・ID による NG・ID 別レス数表示が効かなくなる。識別子での NG は従来どおり |

## 4. 認証設計（別ブランチ）との差分

本指示は認証設計書の次の記述を上書きする。認証ブランチ側の設計書の更新が必要。

- §5.3 `!uid` と ` </b>@uid<b>` → `!id` と ` </b>(@ユーザーID)<b>`。トリップが無くなるので並びは「名前の直後・識別子の前」。
- §2・§3.1 の「ログイン ID は画面に出さない」→ ID/Password・Google 方式は登録したユーザー ID を表示する。
- §8.1 連投規制の照合キー `id`（`ID:` の値）→ ID 廃止により使えない。`ip`・`shiki`・`aid` で構成する。
- §4.1 `BBS_ID_LV` の扱い → ID 廃止により不要。
- §3.4 の `BBS_DISABLE_NUSI`（スレ立て人コマンドの無効化）→ ` (主)` の無効化にも使う。

## 5. 決めたこと（指示に明記が無かった点）

| 点 | 決定 | 理由 |
| --- | --- | --- |
| 名前の `#` 以降 | 捨てる | トリップキーの漏えい防止 |
| `!id`・`!no` の一致範囲 | 直後が英数字・`_` でない `!id` / `!no` | `!none`・`!idol` などの普通の語を巻き込まない |
| 未認証の `!id` | エラーにせず取り除くだけ | 認証設計書 §5.3 に合わせる |
| >>1 の ` (主)` | 付けない | スレ立て人であることは自明 |
| キャップ | `!id`・` (主)` とも対象外、キャップのスレは `owner` を保存しない | 匿名レスとキャップの結びつきを晒さない |
| IPv6 の一致範囲 | /64 | 認証設計書の `keyIp` と同じ。一時アドレスの変化を吸収する |
| 実装上の配置 | 判定は `domain/posting/`（`NameCommands`・`KeyIp`・`ThreadOwner`・`NusiMark`・`PostingUser`）、保存形式は `durable/codec/ThreadOwnerCodec`。投稿処理の `makeId` は `makeShikibetsu` に改名 | AGENTS.md 3.5 |
| 既存スレ | ` (主)` を付けない | `owner` が無く、ユーザー ID は元から無い。log の IP 文字列を解析する互換処理は入れない |

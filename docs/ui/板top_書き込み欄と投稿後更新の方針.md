# 板top：書き込み欄と投稿後のフィード更新の方針

2026-10-29 検討メモ。対象モック: `docs/ui/board.html`（旧 UI）、`docs/ui/3ch-board-thread-v2.html`（新 UI）。

## 0. 前提となる要件

- 板top（スレッドフィード）の各スレから、画面遷移せずに書き込めるようにする。
- 投稿後はその場でフィードを更新し、スレ一覧へ移動しなくても会話を続けられるようにする。
- スレッドが上がった（age）ときの挙動も決めておく。

## 1. 書き込み欄：details/summary とモーダルの比較

| 観点 | details/summary（`board.html` 現状） | モーダル（`<dialog>`） |
|---|---|---|
| JS への依存 | なし。SSR のみで動作する | 開閉と、どのスレに書くか（`key`）の切り替えに island が必要 |
| HTML の量 | スレごとに form を1つずつ出す。無限スクロールでは増え続ける | form は1つ。`bbs` / `key` は開くときに差し込む |
| 書きながら読めるか | 読める。直前のレスや `>>n` を参照しやすい | 背景が隠れる。スレタイや最新数レスをモーダル内に出す必要がある |
| 下書き | 複数のスレで同時に保持できる | 1つずつ。閉じても下書きを残す仕組みが要る |
| 投稿後に会話を続けやすいか | 欄を開いたまま続けて書ける | 閉じて自分のレスへスクロールするのが自然 |
| 新 UI との一貫性 | 新 UI では折りたたみをサイドバーにしか使っていない | 新 UI はスレ立てと表示設定をモーダルにしている |

- `board.html` の書き込み欄は `<form ...></form>` が空のまま閉じており、入力欄がフォームの外に出ている（Wayback が保存した DOM の崩れ）。実装では `<form>` で入力欄を囲むこと。
- 投稿後も書き込み欄を開いたままにする方針（3章・5.4）は、カードの中に欄を置く details 方式と相性がよい。モーダルで同じことをするなら、投稿後も閉じずに追加したレスを見せる必要があり、背景が隠れる問題が大きくなる。
- 段階的に進められる。最初は details で SSR だけで動かし、のちにモーダルの island を足して置き換える。JS が動かない環境では details の欄がそのまま使える。

## 2. 投稿の送り方（bbs.cgi は変更しない）

成功時、bbs.cgi はレスポンスヘッダ `x-threadkey` / `x-resnum` を返す（`Posting.respond`）。結果ページの本文は読まずに、ヘッダだけで判定する。

fetch で送るときの制約（`Posting.checkRequest` / `readForm`）:

- Content-Type は `application/x-www-form-urlencoded` に限られる。`new URLSearchParams(new FormData(form, e.submitter))` に変換して送る（`FormData` をそのまま送ると multipart になって弾かれる）。
- `submit=書き込む` が必要。`FormData` の第2引数に submitter を渡す。
- Referer の検査があるので、同一オリジンから送る。
- エラーでも HTTP 200 が返る。`x-resnum` がなければ失敗とみなし、本文の `<!-- 2ch_X:error -->` 以降のメッセージを入力欄の近くに表示する。
- 下書きは成功したときだけ消す。

JS が動かない環境では普通に POST され、meta refresh で read.cgi に移る。

## 3. 投稿後のフィード更新

- 表示済みの最終レス番号 + 1 から `x-resnum` までを取得して追加する（間に入った他人のレスも含める）。
- レスの取得元は次のどちらか（未決定）。
  - dat を `Range` で差分取得し、`TextDecoder('shift_jis')` でデコードする。既存のもので実現できる。
  - 新 UI 用に、UTF-8 で JSON を返す差分 API を HonoX に新設する。描画を SSR と共通にしやすい。
- 追加したら自分のレスを強調表示する。
- **書き込んだスレの書き込み欄は開いたままにする**（2026-10-30 決定）。本文だけ空にし、名前・E-mail は残す。続けて書き込めるようにするため。

## 4. スレッドが上がったときの挙動

sage でない投稿をすると、Board DO の `updateThreadUnlocked` がそのスレを subject の先頭へ移す。

### 4.1 自分の書き込みで上がった場合

**案A（採用候補）: その場に留める。** カードは動かさず「↑ 上がりました」の印だけ付け、並びは次に読み込み直したときに反映する。

- 案B（先頭へ移して追いかける）は位置を見失わせ、他のスレも読み飛ばさせてしまうので採らない。
- 案C（先頭へ移し、元の位置に目印を置く）は実装が複雑な割に得るものが少ない。

上がったかどうかはクライアント側では判断できない。メール欄の `sage` のほかに、`BBS_FORCE_SAGE` と `BBS_LIVE` による強制 sage があるため（`Posting.prepare`）。成功時のヘッダに **`x-age: 0|1` を追加する**案がある。ヘッダを1つ足すだけなので、専ブラとの互換性（AGENTS.md 3.4）には触れない。

### 4.2 他人の書き込みで上がった場合

フィードはその場では並べ替えない。上部に「上がったスレが N 件あります」という帯を出し、クリックしたときに反映する。

### 4.3 続きの読み込み（無限スクロール）

offset 方式で取得すると、未表示のスレが上がったときに表示済みのスレが後ろへずれ、次のページで重複や取りこぼしが起きる。

- 初回表示のときに subject の並び順（スレの key の一覧、700 行で約 10KB）を確定させてクライアントに持たせ、続きはその一覧の順に取得する。
- 最低限の対策としては、key で重複を除去する。取りこぼしたスレは 4.2 の帯で拾う。

並び順を固定すると、4.1 の案A と同じく「画面上の並びはリロードするまで変わらない」という一貫した動きになる。

## 5. 新規スレッド作成（2026-10-30 追記）

スレ立て後も画面遷移せず、スレッドフィードの最上部に立てたスレを出す。

### 5.1 送信と結果の判定（bbs.cgi は変更しない）

- 送り方は 2章のレス投稿と同じ。違いは `subject` を付けて `key` を空にすることだけ。
- `subject` があると、サーバーは `key` を投稿時刻（unixtime）にする（`Posting.readForm` の後段）。成功時の `x-threadkey` が新しいスレの key、`x-resnum` は 1 になる。
- 失敗時の扱いも 2章と同じ。スレ立て固有のエラー（「別の人が同時刻にスレッドを立てようとしています」、立てすぎ規制、タイトル長超過など）も、作成欄の近くに表示して下書きを残す。

### 5.2 フィードへの差し込み

- `x-threadkey` の >>1 を 3章と同じ取得元から取り、スレのカードを組み立ててフィードの先頭に差し込む。
  - タイトルは送信した値ではなく、取得した dat の1行目の第5フィールドを使う（サーバー側でエスケープや加工が入るため）。
- 4.3 で固定した並び順（key の一覧）の先頭にも新しい key を足す。続きの読み込みで同じスレが重複しないよう、key での重複除去もあわせて行う。
- 「画面の並びはリロードするまで変えない」（4章）の例外は、自分が立てたスレを先頭に出すことだけとする。
- 差し込み後はフィードの先頭までスクロールし、立てたスレを強調表示する。作成欄は閉じて内容を消す。

### 5.3 表示中のタブや条件との関係

| 表示中 | 挙動 |
|---|---|
| スレッドフィード・新着順 | 先頭に差し込む |
| スレッドフィード・勢い順／レス数順、または検索中 | 並び順に関係なく先頭に固定して差し込み、「あなたが立てたスレ」と表示する |
| スレ一覧 | 一覧の先頭行に差し込む |
| おすすめ3ちゃんねる | スレッドフィードのタブに切り替えてから差し込む |

### 5.4 その他

- **立てたスレのカードは、書き込み欄を開いた状態で出す**（2026-10-30 決定。3章と同じ扱い）。>>1 の直後に続けて書き込むことが多いため。
- JS が動かない環境では普通に POST され、meta refresh で新しいスレの read.cgi に移る。
- 新しいスレが subject に入ると、`BBS_MAX_MENU_THREAD` を超えた最古のスレが subject から落ちる。フィードの末尾に表示中であっても、その場では消さない。

# 既知不具合台帳（v5 → v6 移植）

**方針（2026-10-02 改訂）: v6 への移植と本番切替は完了した。ここに挙げた不具合は修正してよいが、AGENTS.md §3.3 の手順に従う。**

移植中は「v5 とバイト単位で同一な出力」を検証の軸にするため、不具合を直さず記録だけにしていた。
v5 のソース（`src/`）と v5 との差分テストは廃止した（v5 はタグ `v5-final`）ので、その制約は無くなった。
ただし ID / トリップ / キャップの値や dat 構造に触れる修正は既存ユーザーへの影響が大きいため、承認を得てから行う。
表の「`src/...`」「`common.js`」等はタグ `v5-final` 上のファイルを指す。

- **記録先**: 本ファイル。新たに発見した不具合は下表に追記する。
- **固定先**: `tests/*.test.js`（v6 の現仕様固定テスト）。各アサーションのコメントに `KB-xx` を記載して対応付ける。
- **修正時**: 対応アサーションを新挙動へ更新し、ステータスを更新する。1 件ずつ独立したコミットにする。

### Shift_JIS 方針の経緯（KB-04 / KB-17 / KB-18）

**現在の扱い（2026-09-23 続行時）:** 利用者の「仕様を変えない」と追加の AGENTS.md を優先し、step 3 は未対応文字を含めて現行互換とする。以下のライブラリ置換案は保留であり、有効化していない。KB-04 / KB-17 / KB-18 は残存する。

**2026-09-23、利用者の指示による方針変更。** Shift_JIS 変換は自前テーブルを忠実に移植せず、
Scala.js 移植と同時に `encoding-japanese` へ移行する。これにより KB-04 / KB-17 / KB-18 の3件は
**移植完了を待たずに解消される**。

そのため Shift_JIS 変換についてのみ「バイト単位で完全一致」は成立しない。
代わりに、**差異が出る入力を全件列挙して確定リストとして持つ**ことを受け入れ基準とする
（詳細は [移植方針_step3_ScalaJS.md](移植方針_step3_ScalaJS.md) R-01）。
v5 が正しく変換できていた文字については、引き続きバイト単位の一致を要求する。

**2026-09-23、実装完了（案A確定・実装済み）。** 単純な `encoding-japanese` 置換では
CP932 重複符号（NEC特殊文字行 `0x87xx` 等）で v5 との不一致が生じることが判明したため、
**NEC重複符号の双方向互換マッピングを追加した**（`bbs/src/main/scala/ch3s/bbs/util/SjisEncoding.scala`）。
これにより「v5が正しく変換できていた文字」には重複符号文字も含めてバイト単位の一致が成立し、
KB-04 / KB-17 / KB-18 が実際に解消された（残る差異は IBM拡張行・絵文字等 v5 が元々変換できなかった
入力のみ）。マッピングは9文字の決め打ちではなく、v5の実測データ全件との機械的な突き合わせで
抽出した（10件 + 置換文字救済1件の計11件）。詳細は [sjis差異一覧.md](sjis差異一覧.md) 参照。

**2026-09-23、案Aを破棄し「v5と同じ構築手順」へ差し戻し（最終決定）。** 案Aの実装・実測後、
採用根拠だった3点がいずれも崩れた: (1) KB-04は「v5のテーブルが不完全」という仕様調査自体が
誤りで、実際の穴はIBM拡張行`0xF0`-`0xFC`と絵文字のみ、(2) 「ランタイム構築はNode/workerdで
表が変わって危険」(R-06)という懸念は実機`wrangler dev`上での直接突き合わせにより否定された
（説明のつかない差異0件）、(3) `encoding-japanese`はv5と重複符号の採用側が食い違い、
これを補うための11件の互換マッピングそのものが不要な複雑さだった。加えて素の
`encoding-japanese`呼び出しはテーブル参照より2.8〜5.4倍遅い。以上により、
`SjisEncoding.scala`はv5の`sjis`クラスのコンストラクタ（`new TextDecoder('sjis')`による
テーブル構築）を逐語的に再現する方式に戻し、`encoding-japanese`依存とNEC重複符号マッピング
（11件）は完全に撤去した。意図的な差異はKB-17（encodeのNULバイト→NCRフォールバック）と
KB-18（decodeの`TypeError`送出/無音破棄→`?`フォールバック）の**2件のみ**に整理され、
KB-04は「そもそも実装しない」ことで（encoding-japanese導入前のv5同様の状態に）解消のまま
維持される。詳細は [移植方針_step3_ScalaJS.md](移植方針_step3_ScalaJS.md) R-01 / R-06、
[sjis差異一覧.md](sjis差異一覧.md) 参照。

### 例外: 実際に悪用可能なセキュリティ欠陥

「移植まで修正しない」の唯一の例外。**現行本番環境で実際に悪用可能**なセキュリティ欠陥を見つけた場合は、
台帳に記録したうえで**利用者に報告し、先行修正するかどうかの判断を仰ぐ**。勝手に直さないが、黙って抱え込みもしない。
該当しうるもの: XSS、認証バイパス、任意コード実行、情報漏洩。
**現時点で該当するものは無い。** KB-22 は候補として検討したが、到達可能性を検証した結果、悪用不可と判断して通常扱いに戻した。

## KB-27: クライアントバンドルへのサーバ処理混入

- **分類 / 状態**: ビルド・コード公開 / 修正済（2026-10-05、利用者指定の Claude Code レビュー実施済み）。
- **現象**: ローカルの `dist/static/client.js`（358,907 bytes）に `Posting`、`AdminHandler`、`Moderation`、`PublicRoutes`、暗号・Shift_JIS 処理が含まれる。
- **原因**: `build.sbt` が `bbs-client` のソースを `bbs` に取り込み、`vite.config.ts` の client ビルドも `projectID: "bbs"` を指定している。`@JSExportTopLevel` の moduleID による export 先の分離だけでは依存実装は隔離されず、生成された `bbs/target/scala-3.3.8/bbs-opt/client.js` がサーバ処理を含む `internal-39b2529253111025cee9e8cbe7ef714abef3b3de.js` を import している。Rollup は内部モジュールの副作用を保全するため、その実装を残す。
- **検証**: 既存の Scala.js 生成物の `client.js` を入口として、インストール済み Rollup でメモリ上の再バンドルを実施。通常の `moduleSideEffects: true` では 874,662 bytes（非 minify）で Posting が残り、診断用の `false` では 114 bytes で内部モジュールが除去された。後者は原因切り分けの実験であり、全モジュールの副作用を無視する設定の採用を意味しない。
- **影響**: ブラウザ向け成果物にサーバ実装が含まれ、容量も増加する。`wrangler.jsonc` は `dist` を Static Assets の対象としている。本番での取得可否・配置済みファイルは今回未確認。`ADMIN_PASSWORD` というプロパティ名の存在は確認したが、秘密値の漏えいを示すものではない。
- **対応方針**: 既存の独立した `bbsClient` プロジェクトで client をリンクし、`bbs` から client ソースの取り込みを外す。現行 npm スクリプトは client/server を直列にビルドしており、単一プロジェクト化の理由だった同時 sbt 起動の回避と両立できる。修正時にはクライアント成果物へのサーバ処理混入がないことを検証する。
- **出典**: 修正前の `build.sbt:57–62,81–89`、`vite.config.ts:25,69`、`app/client.ts:7`、上記ローカル生成物および Rollup 実測。
- **修正・検証**: client の `projectID` を `bbsClient` に変更し、`bbs` へのクライアントソース取り込みを削除した。`npm run v6:build` と型チェックが成功し、`dist/static/client.js` は 11,444 bytes になった。`tests/client-bundle.test.js` で static 配下の JS にサーバ専用の識別子・文字列が残らないことを検証。サーバのハンドラ・ストレージ・公開プロトコルは変更していない。Origin 検証の削除は利用者確認済みの現仕様として、対応するテストと仕様書を更新した。`sbt test` と `npm test` は成功。レビュー記録は `docs/client-build-review.md`。

# www.3ch.io への移行

## コードの対応

- 入口・掲示板一覧・ガイド・3chiko のリンクは `https://www.3ch.io` を使用する。Wiki・メール・旧サービスの別サブドメインは今回の対象外。
- 投稿 Referer は新旧の正確なホストとローカル開発用ポートを許可する。PON Cookie は Domain を指定せず、応答したホストに保存する。ドメインをまたいで Cookie は引き継がれない。
- 旧ホストの subject.txt 先頭には `0000000000.dat` の仮想告知スレを追加する。同じキーが既存一覧にある場合は追加せず、既存 dat がある場合は既存内容を優先する。DO/R2/KV には保存しない。
- 仮想告知には新ホスト側の実在スレがないため、告知本文の「スレURL」行を省略し、BBSMENU・板URL を案内する。
- 旧ホストの既存 dat は第1レス本文末尾に `<hr>` から始まる移転告知を追加する。5フィールド・本文末尾の空白・保存データは維持する。新ホストの dat は従来どおり。
- 既存専ブラキャッシュと告知付き dat のバイト位置が異なるため、旧ホストの既存 dat では Range と If-Modified-Since を無視し、200 の全文で再取得させる。新ホストの Range/304 は変更しない。仮想告知 dat は内容が固定のため Range/304 を使用できる。
- 旧ホストへの巡回は毎回全文200になるため、差分取得より転送量が増える。旧ホストの告知付きキャッシュを新ホストへコピーした専ブラは、バイト位置が異なるため新ホストで dat の再取得が必要になる場合がある。
- 3chiko の旧ホスト表示では第1レス本文末尾にも案内を表示する。

## 手動作業

Cloudflare Dashboard のリダイレクト設定は別途行う。Worker 内にはリダイレクトを実装しない。

1. `www.3ch.io` を既存 Worker に接続し、TLS と新旧ホストでの閲覧・投稿を確認する。
2. `www.3chbbs.com` のブラウザ閲覧を、パスとクエリ文字列を保持した `https://www.3ch.io` へ 301 リダイレクトする。
3. User-Agent に Monazilla を含むリクエスト、および `bbs.cgi`（`subbbs.cgi` を含む）・dat・subject.txt・SETTING.TXT はリダイレクト対象から除外する。包括的な旧ホスト全体転送を先に有効化しない。
4. R2 の独自 `bbsmenu.html`・`head.txt`・SETTING.TXT 等に保存された旧 URL は管理画面で確認し、必要に応じて手動更新する。本変更は保存済みデータを書き換えない。
5. GitHub リポジトリ名変更は別途手動で行う。

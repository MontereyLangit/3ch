## 1. システム概要・全体アーキテクチャ

### 1.1 技術スタック
- **ランタイム**: Cloudflare Workers (ES Modules, compatibility_date: v5 は 2025-09-19、v6 は 2026-08-04。後者は nodejs_compat 既定有効)
- **状態管理・並行制御**: Cloudflare Durable Objects (DO)
  - `Board` (板単位 DO): スレッド一覧 (`subjectList`)、削除済みスレッド一覧 (`removed`) の管理、age/sage ソート
  - `Thread` (スレッド単位 DO): スレッドデータ (`dat`)、投稿者ログ (`log`)、スレ設定 (`settings`)、状態フラグ (`hidden`, `stopped`, `movedTo`)、排他制御（`blockConcurrencyWhile`）
- **オブジェクトストレージ**: Cloudflare R2
  - `ch3www` (バケット: `3ch`): 静的設定ファイル (`{bbs}/SETTING.TXT`, `{bbs}/head.txt`)、全体ヘッドライン (`headline.txt`)、規制リスト (`deny.cgi`, `ngwords.cgi`)、板一覧 (`bbsmenu.html`)、過去ログ目次 (`{bbs}/thread/subject.txt` など)、旧データアーカイブ (`.cgi`)
  - `ch3img` (バケット: `img3ch`): 画像ストレージ（現行 Workers 内未参照）
- **Key-Value**: Cloudflare KV
  - `CAP`: キャップ情報 (パスワードハッシュ -> 表示名)
  - `TEST` / `TMP`: 一時データ用
- **暗号・ハッシュ**: Web Crypto API (SHA-1, SHA-256)。v5 は独自実装の MD5・Unix crypt(3) DES も使っていたが、v6 では廃止した（タグ `v5-final` 参照）
- **文字コード**: 自前 TextDecoder/TextEncoder ベースの Shift_JIS エンコーダ/デコーダ（JIS X 0208）

### 1.2 アーキテクチャ構成図
```
[ ユーザー / 専ブラ / Webブラウザ / 管理者 ]
                        │
                        ▼
            [ Cloudflare Workers ]
          (main.js / admin.js / common.js)
            │           │              │
    (投稿/スレ立て)   (閲覧)         (管理)
            │           │              │
            ▼           ▼              ▼
     [ bbs.cgi.js ] [ Board DO ]   [ /admin/* ]
     [moderation.js]─── subjectList    │
            │       ─── removed        │
            │                          │
            ▼                          │
     [ Thread DO ] ◄───────────────────┘
       ─── dat (2ch互換dat)
       ─── log (投稿者userInfo)
       ─── settings (スレ設定)
       ─── hidden / stopped / movedTo
            │
            │ (旧形式 .cgi 移行フォールバック)
            ▼
     [ R2 Storage (ch3www) ]
       ─── SETTING.TXT, head.txt, bbsmenu.html
       ─── headline.txt, deny.cgi, ngwords.cgi
       ─── 過去ログ目次 (thread/subject.txt)
     [ Workers KV (CAP) ]
```

## 3. データモデル・ストレージ永続化フォーマット

### 3.1 スレッド dat 形式 (`Thread DO` 内 `dat`)
伝統的な 2ch 互換 dat 形式（LF区切り、各行5フィールド）。
```
名前<>メール<>日付<> 本文 <>スレッドタイトル\n
名前<>メール<>日付<> 本文 <>\n
名前<>メール<>日付<> 本文 <>\n
```
（2026-11-02 変更: トリップ・ID を廃止し、`!id`・スレ主表示を追加。[トリップ・ID廃止とスレ主表示.md](トリップ・ID廃止とスレ主表示.md)）
- **フィールド区切り**: `<>`
- **第1フィールド (名前)**: `名前` + ユーザーID(` </b>(@userId)<b>`。`!id` 指定かつ認証済のとき) + 識別ID(` </b>(shikibetsuId)<b>`) + スレ主(` (主)`。§6.5)
  - 未入力時: 板設定 `BBS_NONAME_NAME`（既定: `名無しさん＠３ちゃんねる`）
  - キャップ時: `名前＠ハンドル ★` または `ハンドル ★`
  - 識別ID非表示設定（`BBS_ID_SHIKIBETSU=d`）でも、現行コードでは末尾に空の ` </b>()<b>` が付加される。
- **第2フィールド (メール)**:
  - **現行の実装**: レス投稿行のメールフィールドは**常に空文字**（`name<><>date...`）。入力されたメールアドレスは sage 判定やキャップ認証に使用されるのみで、dat の第2フィールドには保存されない。
- **第3フィールド (日付)**: `YYYY/MM/DD(曜日) HH:mm:ss`
  - 新規投稿時は秒まで（ミリ秒 `.SS` は付かない）。
  - 2026-11-02 まではこの後に ` ID:xxxx`（キャップは `ID:???`）が付いていた。過去の行はそのまま残る。
- **第4フィールド (本文)**:
  - HTML特殊文字エスケープ済み。
  - 改行は ` <br> `。
  - **極めて重要**: 専ブラ互換のため、本文フィールドの**前後に必ず半角スペース**が入る（` <> MESSAGE <> `）。
- **第5フィールド (タイトル)**:
  - **1レス目 (>>1)**: スレッドタイトルが入る（2026-11-02 まではスレ立て時の ID が ` [ID:xxxx★]` として末尾に付いていた）。
  - **2レス目以降**: 空文字（行末は `<>\n`）。

#### あぼーん（レス削除）の形式
- `moderate('deleteRes')`: `あぼーん<>あぼーん<>あぼーん<>あぼーん<>{1レス目のみ元のタイトル}`
- 旧 `deleteRes()`: 全フィールドが `あぼーん<>あぼーん<>あぼーん<>あぼーん<>あぼーん`

### 3.2 投稿者ログ形式 (`Thread DO` 内 `log`)
監査・規制判定用のアクセスログ（LF区切り）。
```
{レス番号}<>{userInfo}\n
```
- `userInfo` 書式:
  `UID:{uid} IP:{host} AS{asn}-{country},{ken},{city}Device:{deviceInfo} UA:{userAgent}`

### 3.3 スレ設定形式 (`Thread DO` 内 `settings`)
スレ立て時の設定スナップショット。
```
KEY1=VALUE1<>KEY2=VALUE2<>...<>
```

### 3.4 板スレ一覧形式 (`Board DO` 内 `subjectList`)
```
{key}.dat<>{スレッドタイトル} ({レス数})\n
```
- 保持行数上限: `BBS_MAX_MENU_THREAD`（設定ファイル不在時は 300、未設定時は 700）。
- 容量上限: 512KB（超過時は末尾から古い行を削除）。

### 3.5 削除済みスレ一覧 (`Board DO` 内 `removed`)
削除または別板へ移動されたスレッド key の配列（JSON配列）。

### 3.6 全体ヘッドライン形式 (`R2: headline.txt`)
```
{最終更新UnixTimestamp}\n
{板dir名}<>{板名}<>{最終更新UnixTimestamp}<>{スレッドキー}<>{本文先頭30文字}\n
```
- 最大保持件数: 300板。

### 3.7 過去ログ目次形式 (`R2`)
- **区分目次 (`{bbs}/thread/subject.txt`)**:
  ```
  {最終更新UnixTimestamp}\n
  {key上位4桁}<>{作成時UnixTimestamp}\n
  ```
  ※注: 「年別」ではなく「スレッドkeyの上位4桁（Unixタイムスタンプの先頭4桁区切り）」である。
- **スレッド目次 (`{bbs}/thread/{kako}/subject.txt`)**:
  ```
  {最終更新UnixTimestamp}\n
  {key}<>{title}<>{名前}<>{shikibetsuId}<>{id}<>{>>1本文}\n
  ```
  ※注: `{id}` は 2026-11-02 の ID 廃止以降は空文字（フィールド数は保つ）。それ以前の行の title は、スレタイ末尾の ` [ID:xxxx★]` 付加前の元タイトルである。

### 3.8 旧形式スレッドログ (`.cgi`) とオンデマンド移行仕様
DO に `dat` が存在せず、`0 < key < 1762009199` の場合、R2 `ch3www` の `${bbs}/thread/${key.slice(0,4)}/${key}.cgi` から取得して DO へ移行する。

1. **`.cgi` の構造**:
   - 1行目: スレッドタイトル
   - 2行目: スレ設定 (`KEY=VALUE<>...`)
   - 3行目以降: `0:num<>1:name<>2:sikibetsuId<>3:time<>4:id<>5:MESSAGE<>6:HOST999`
2. **変換規則**:
   - 欠番（レス番飛び）は `j + "<>あぼーん<>あぼーん<>あぼーん<>あぼーん\n"` で埋める。
   - `time`（10桁秒+ミリ秒）を JST `YYYY/MM/DD(曜日) HH:mm:ss.SS` に変換。
   - 名前末尾に ` </b>(${sikibetsuId})<b>`、日付末尾に ` ${id}` を結合。
   - 本文の `<br>` を ` <br> ` に置換。
   - 1レス目末尾にスレッドタイトルを結合。
   - 変換した dat を `this.state.storage.put('dat', dat)` で永続化。
   ※現行コードでは原文全体を `legacyLog`、2行目を `settings` に保存する。新形式の `log` は再構成しない。`dat` だけという旧記述を訂正（2026-09-23）。

## 4. Durable Objects 状態モデルと内部メソッド

### 4.1 Thread DO (`src/durable_objects/thread.js`)

#### 保持ステート
- `dat` (string): 全レスデータ
- `log` (string): 全投稿者ログ
- `settings` (string): スレ設定
- `hidden` (boolean): 論理削除フラグ（true の場合、閲覧は 404、投稿は拒絶）
- `stopped` (boolean): 書き込み停止フラグ（true の場合、閲覧は可能、投稿は拒絶）
- `movedTo` (string): 移動先情報（`targetBoard/targetKey`）
- `owner` (object, v6 で追加): スレ主判定用 `{ip, shikibetsu, account}`（§6.5）。スレ立て時に保存し、`move` で移動先へ引き継ぐ

#### 提供メソッド
- `getDat(bbs, key)`: `hidden` なら空文字。dat 未保持時は旧DO（keyのみ）または R2 `.cgi` からインポートして返却。
- `getLog()`: 投稿者ログを返却。
- `getSettings()` / `setSettings(newSettings)`: スレ設定の取得・更新。
- `getOwner()`（v6 で追加）: `owner` を返却（無ければ空）。
- `addRes(datLine, logLine, posting)`:
  - `this.state.blockConcurrencyWhile` による排他制御下で実行。
  - `stopped` または `hidden` ならエラー。
  - dat 行数からレス番号（`count`）を再計算し、dat と log を追記。
  - **重要**: メソッド内部で `BOARD_DO.updateThread` を呼び出し、板のスレ一覧を更新する。
- `inspect(bbs, key)`: 管理画面用。現在の dat, log, hidden, stopped, movedTo を一括返却。
- `moderate(action, data)`:
  - `delete`: `hidden = true` を設定し、`BOARD_DO.removeThread(key)` を呼ぶ。
  - `stop`: `stopped = true` を設定。
  - `resume`: `stopped = false` を設定。
  - `editRes`: 指定レスの名前・メール・本文を置換（1レス目のタイトルは維持）。
  - `deleteRes`: 指定レスのフィールド0〜3を「あぼーん」に置換（1レス目のタイトルは維持）。
  - `move`: 移行先 Thread DO を取得してデータを移管し、自身を `hidden = true, movedTo = target` に設定。旧 Board DO から削除し、新 Board DO にスレッドを追加。

### 4.2 Board DO (`src/durable_objects/board.js`)

#### 保持ステート
- `subjectList` (string): 2ch互換スレ一覧
- `removed` (Array<string>): 削除・移動されたスレッド key の配列

#### 提供メソッド
- `getSubject()`: `subjectList` 文字列を返却。
- `getRemoved()`: `removed` 配列を返却。
- `removeThread(key)`: `subjectList` から該当スレ行を削除し、`removed` に key を追加。
- `updateThread(threadData, isSage, maxThreads)`:
  - `isSage === true`: 該当行のレス数 `({resNum})` のみをその場で置換（位置は維持）。
  - `isSage === false`: 該当行を削除し、一覧の先頭に `{key}.dat<>{title} ({resNum})` を挿入。
  - 行数が `maxThreads` を超えた場合は末尾を切り捨て。
  - 全体バイト数が 512KB を超えた場合は末尾行を順次削除。

## 5. 投稿・スレ立てパイプライン詳細ロジック（bbs.cgi）

### 5.1 リクエスト検証 (`checkRequest`)
1. **HTTP メソッド**: `POST` 必須（それ以外は「POST メソッドを使ってください。」）。
2. **Content-Type**: `application/x-www-form-urlencoded` 必須。
3. **Referer 検証**:
   - 新旧の `http(s)://www.3ch.io` / `http(s)://www.3chbbs.com` または `http://127.0.0.1:8787` / `http://127.0.0.1:8788`（ローカル開発用）の正確なホスト・ポートであること（2026-11-04）。
   - ※注意: 新旧ドメインとも HTTP の専用ブラウザを引き続き許可する。移転告知・旧ホストの dat 全文再取得方針は `ドメイン移行.md` を参照。
4. **User-Agent 検証**:
   - 長さ: 7〜384 バイト。ASCII印字可能文字（`0x20`〜`0x7E`）のみ許可。
   - `Monazilla/1.00` で始まる場合は `isMonazilla = 1`。
   - Client Hints (`sec-ch-ua-full-version-list` または `sec-ch-ua`) を UA に追記。
   - `Accept`, `Accept-Language`, `Accept-Encoding` を `browserInfo` に記録。
5. **IP・プロキシ検証**:
   - `CF-Connecting-IP` を取得。
   - `client-ip` ヘッダが存在する場合は「変な情報が送られて来ました。」でエラー。
   - `X-Forwarded-For`, `Forwarded`, `Via` があればホスト文字列に `<...>` で追記。
   - IPv6 の場合、ID計算用の種（`idnotane`）は先頭4ブロック（`/64` 相当）。IPv4 は IP そのもの。

### 5.2 フォームボディ解析 (`readForm`)
1. **エンコーディング判定**:
   - ボディ内の `submit=` パラメータを走査。
   - `%e6%9b%b8`（UTF-8「書」）を含む場合: `isSJIS = 0`（Webブラウザ）。
   - 含まない場合: `isSJIS = 1`（専ブラ）。※専ブラ以外（UAが `Monazilla/1.00` 以外）で Shift_JIS 投稿された場合は「書き込みボタンを押忍べし」エラー。
2. **サニタイズ処理**:
   - URLデコード後、以下の文字置換を実行:
     - `&` (文字実体参照以外) -> `&amp;`
     - `"` -> `&quot;`, `<` -> `&lt;`, `>` -> `&gt;`, `'` -> `&apos;`
     - `\t` -> 半角スペース
     - `&#0*1[03];` および `&#[xX]0*[aAdD];` -> `<br>`
     - `\r\n`, `\n`, `\r` -> `<br>`
     - 制御文字 `\x00`〜`\x1F`, `\x7F` を除去
   - 特殊記号変換: `★` -> `☆`, `◆` -> `◇`, `＃` -> `#`
3. **トリップキーの除去**（2026-11-02 からトリップは廃止）:
   - 名前欄末尾の `#` 以降を取り除いて捨てる。
   - 続けて名前欄のコマンド `!id`・`!no`（直後が英数字・`_` でないもの）を取り除く（§6.5）。
4. **特殊コマンド・ルーティング**:
   - `key` が `9` 始まり、かつ本文が `!newthread` で始まる場合: 本文先頭からスレタイを抽出しスレ立てに変換。
   - `key` が `924` または `900` 始まりの場合: 板名 `bbs` を強制的に `"924"` に書き換え（全板共通スレ。詳細は [全板共通スレ](global-thread.md)）。
   - **禁止板名**: `bbs` が `""`, `"test"`, `"js"`, `"css"`, `"html"`, `"images"` の場合は拒否。
   - **板名の形式**: 板設定取得の段（`boardSettings`）で、`bbs`（前段で `[^a-zA-Z0-9_-]` を除去済み）が `[a-zA-Z0-9]{1,16}`（`BoardId`）でなければ、同じ文言（`板の指定が不正です。`）で拒否。返信でも検証する（v6 で追加。`-` `_` を含む・17文字以上の板名には書き込めない）。
5. **スレ立て/レス判定**:
   - `key` が空で `subject` がある場合: スレ立て (`key = unixtime`, `number = 1`)。
   - `key` がある場合: レス投稿 (`subject` は空文字化)。
   - **全板共通スレ（2026-11-01 追加）**: スレ立てで本文先頭が `!924` / `!900` の場合、命令と直後の空白・`<br>` を本文から除き、
     `key` の先頭3桁を `924` / `900` に置き換え、`bbs` を `"924"` にする。キャップ認証後に★でなければ拒否する。
     924 スレへのレスも★のみ（`checkGlobalThread`）。詳細は [全板共通スレ](global-thread.md)。

### 5.3 フィールドサイズ検証 (`checkFieldSize`)
- 強キャップ（`strongCap = 1`）または `!ADMIN:` コマンドで始まる本文は検証をスキップ。
- **文字数チェック（JavaScript `.length` = UTF-16コード単位）**:
  - `subject.length > BBS_SUBJECT_COUNT` (既定: 64)
  - `FROM.length > BBS_NAME_COUNT` (既定: 64)
  - `mail.length > BBS_MAIL_COUNT` (既定: 64)
  - `MESSAGE.length > BBS_MESSAGE_COUNT` (既定: 4096。ただし **>>1 は最大 65536** まで自動拡張)
- **行数チェック (>>2 以降のみ)**:
  - `MESSAGE.split("<br>").length > BBS_LINE_NUMBER * 2` (既定 30 の場合、`<br>` 分割要素数が 60 を超えるとエラー)。
- **名無し補完**:
  - `FROM` が空の場合、板設定 `BBS_NONAME_NAME`（既定: `名無しさん＠３ちゃんねる`）を設定。

### 5.4 投稿完了・エラーレスポンス

2026-10-15追加のスレ立て履歴規制は [bbs.cgi スレ立て規制](thread-creation-regulation.md) を参照。
板ごとの直近件数と有効期間でIP・タイトル・UA・AS＋県を照合し、dat保存前にBoard DOで判定・予約する。

- **完了時 (`respondEndHtml`)**:
  - HTTP ステータス: `200 OK`
  - ヘッダ: `x-threadkey: {key}`, `x-resnum: {number}`
  - 内容: `/test/read.cgi/{bbs}/{key}/` を対象とする5秒後のmeta refreshを含む HTML（実装に合わせて訂正。旧期待値の不一致はKB-31）。
- **エラー時 (`respondError`)**:
  - HTTP ステータス: `200 OK`
  - 内容: `<!-- 2ch_X:error -->` および `<font color=#FF0000><b>ERROR: {errMsg}</b></font>` を含む HTML。
  - ※Referer 不正・User-Agent 不正のメッセージは `errMsg` 自体が `"ERROR: "` で始まるため、
    最終的な表示が `ERROR: ERROR: ...` と二重になる（KB-24）。
  - ※2ch専ブラは HTTP 200 かつ HTML 内のコメントマーカーで成功/失敗を判定する。

## 6. ID・識別ID・トリップ・キャップ暗号化仕様

### 6.1 トリップ（2026-11-02 廃止）
名前欄の `#` 以降（従来のトリップキー）は切り出して**捨てる**（表示も保存もしない）。`◆→◇` などの置換は残す。
廃止前のアルゴリズム（Shift_JIS 化したキーの長さで 10 桁 DES・12 桁 SHA-1・`#`+16 進 16 桁の特殊 DES に分岐。KB-13 / KB-14 / KB-19 / KB-26）は
タグ `v5-final` の `src/common.js` と、本書の同タグ版 §6.1 を参照。

### 6.2 キャップ認証仕様 (`processCap`)
メール欄に `#パスワード` を入力して投稿。

1. **照合ハッシュ生成**:
   - パスワード先頭が `!` の場合: 先頭 `!` を除いた文字列をそのままキーとする（旧仕様）。
   - 通常: `SHA-1(SHA-256(pass + saltHash))` の Base64 先頭27文字。`saltHash` は `SHA-256(salt)` の16進。
     ※ `hash("SHA-256", pass + saltHash)` は **16進数文字列** を返す点に注意。
     （v5 は `SHA-1(SHA-256(MD5(pass) + MD5(salt)))`。2026-11-09 に MD5 を廃止。旧式はタグ `v5-final` 参照）
2. **KV 照合 (`CAP` バケット)**:
   - 取得したハンドル名末尾が `★` の場合: `strongCap = 1`（強キャップ、制限バイパス）。
   - 表示名:
     - 名前あり: `名前＠ハンドル ★`
     - 名前なし: `ハンドル ★`
   - キャップ投稿時は `gb.shikibetsuId = "★"`（2026-11-02 までは `gb.id = "ID:???"` も設定していた）。

### 6.3 ID（2026-11-02 廃止）
日付欄の `ID:xxxxxxxx`（IP の先頭部分・板・日付のハッシュ）、`BBS_ID=siberia` の `発信元:IP`、`BBS_ID_LV` の `10` 付加、
スレタイ末尾の ` [ID★]` は出さない。`BBS_ID`・`BBS_ID_LV` は読まない。識別子と共通の日付境界は次のとおり残る。
```javascript
const dateSalt = Math.floor((parseInt(unixtime) + 32400) / BBS_ID_RESET); // JST午前0時基準
```

### 6.4 識別ID 生成仕様 (`shikibetsuId`)
板設定 `BBS_ID_SHIKIBETSU` に応じた名前欄末尾の識別子。
- **`checked` (デフォルト)**:
  `{country}.{kenHash}.{cityHash} {asnHash}-{uaHash}`
  - `kenHash`: `sha1Base64(sha256(ken + idGroup + dateSalt + saltHash)).slice(0, 2)`
  - `cityHash`: `sha1Base64(sha256(city + "c" + idGroup + dateSalt + saltHash)).slice(0, 2)`
  - `asnHash`: `sha1Base64(sha256(asn + idGroup + dateSalt + saltHash)).slice(0, 2)`
  - `uaHash`: `sha256(userAgent + idGroup + dateSalt + saltHash).slice(0, 16)`（`sha256` は16進出力。v5 は md5）
- **`raw`**: `{country}.{ken} {asn}`
- **`ken`**: `{country}.{ken}`
- **`city`**: `{country}.{ken}.{city}`
- **`as`**: `{asn}`
- **`d`**: 空文字（ただし名前欄には ` </b>()<b>` が残る）

### 6.5 ユーザーID表示（`!id`）とスレ主表示（` (主)`）（2026-11-02 追加）
- 名前欄の `!id`（Web 版はフォーム項目 `showid`）: 認証済なら名前の直後に ` </b>(@ユーザーID)<b>` を付ける。未認証・キャップは取り除くだけ。
- スレ主: スレ立て時に Thread DO の `owner` に IP（IPv6 は /64）の salt 付きハッシュ・識別子・アカウントのハッシュを保存し、
  >>1 は常に、返信はいずれか（空でないもの）が一致したら名前欄末尾に ` (主)` を付ける。`!no`・`BBS_DISABLE_NUSI=checked`（板またはスレ）・キャップでは付けない。
- 詳細と判断の経緯は [トリップ・ID廃止とスレ主表示.md](トリップ・ID廃止とスレ主表示.md)。

       - `isWord` の場合: `NGワード禁止！`

## 10. 専ブラ互換・HTTPプロトコル処理仕様

### 10.1 専用ブラウザの識別と Shift_JIS 変換
1. **識別**: `User-Agent: Monazilla/1.00 ...` で判定。
2. **文字コード変換**:
   - 内部は UTF-8 で処理。レスポンス送信時に自前 `sjis` クラスで Shift_JIS バイト配列にエンコード。
   - 専ブラからの投稿は Shift_JIS の URL エンコードボディをデコード。

### 10.2 HTTP Range 差分取得（206 Partial Content）
- **リクエスト**: `Range: bytes={start}-{end}`
  - 終了未指定（`bytes=1000-`）: `start = 1000`, `end = totalBytes - 1`
  - 終了指定（`bytes=100-500`）: `start = 100`, `end = 500`
- **エラー処理**:
  - `start >= totalBytes` または `start > end`:
    - ステータス: `416 Requested Range Not Satisfiable`
    - ヘッダ: `Content-Range: bytes */{totalBytes}`
  - 書式不正: `400 Bad Request`（ボディ: `Bad Range Header`）
- **正常応答 (206)**:
  - ステータス: `206 Partial Content`
  - ヘッダ:
    - `Content-Range: bytes {start}-{end}/{totalBytes}`
    - `Accept-Ranges: bytes`
    - `Content-Length: {end - start + 1}`
    - `Content-Type: text/plain;charset=Shift_JIS`
    - `Last-Modified: {最終レス日時(UTC)}`

### 10.3 条件付き GET（304 Not Modified）
- `If-Modified-Since` の受信時、dat の最終レス日時と比較し、更新がなければボディなし `304 Not Modified`（`Last-Modified` 付き）を返却。

# bbs.cgi スレ立て規制

2026-10-15。作業メモをもとに、スレ立て規制を実装。広域の組み合わせは利用者確認により AS＋県を採用する。
認証・Lv・セッションID・連投規制は今回の対象外。

## 判定

板ごとに、通常は同一IPまたは同一スレタイ、広域は同一User-Agentまたは同一ネットワークグループを拒否する。
日本国内のネットワークグループはAS＋県。指定ASNは県で分けずAS全体、海外は国・ASによらず海外全体。
Cloudflareの位置情報が未取得の場合はネットワークグループを空として扱い、未知の投稿者同士をまとめない。
UAはUser-Agentヘッダーそのものを使う。Client Hintsの変更だけでは回避できない。
IPv6の表記はURLの正規化を使って揃える。タイトルはフォーム処理後・投稿者ID付加前の値を使う。

通常・広域それぞれ、確定履歴を新しい順に指定件数だけ取り、そのうち期限内の履歴と照合する。
期限とちょうど同じ時刻は対象とする。拒否や返信は履歴を進めない。saku板もこの規制の対象。
キャップ（★）のスレ立ては判定せず、履歴にも記録しない（2026-10-17 利用者指示）。設定不正による拒否も受けない。
段 D（2026-11-07）でこの除外を板設定 `BBS_THREAD_PASS`（回避レベル。既定 `privileged`）に置き換えた。既定ではキャップに加えて権限者（管理・削除・規制）の名無しのスレ立ても免除する。免除した投稿は従来どおり判定も記録もせず、設定不正でも拒否しない。
板をまたいで履歴は共有しない。スレ削除・移動によって履歴は解除しない。

`PostingContext` の板・スレキーは値オブジェクト `BoardId`（英数字1〜16文字）・`ThreadKey`（9〜10桁の正整数）で持つ。
既存の板名検証（`[a-zA-Z0-9_-]`）より狭いが、利用者確認によりBoardId側を正とする。
制約外の板では新規スレ立てを「板の指定が不正です。」で拒否する。返信・公開ルート・管理画面の板名検証は今回変更していない。

| SETTING.TXT | 既定値 | 意味 |
| --- | --- | --- |
| `BBS_THREAD_TATESUGI` | `1` | 通常の件数窓。0で無効 |
| `BBS_THREAD_TATESUGI_RESET` | `3600` | 通常の有効期間（秒） |
| `BBS_THREAD_JUNBAN` | `1` | 広域の件数窓。0で無効 |
| `BBS_THREAD_JUNBAN_RESET` | `3600` | 広域の有効期間（秒） |
| `BBS_THREAD_JUNBAN_AS_ONLY` | 空 | 国内でAS全体にまとめるASN。空白・カンマ区切り。`AS2516` 形式も可 |

件数は0〜1000、期間は0〜315360000秒。期間0では同一時刻の履歴だけを対象にする。
旧 `BBS_THREAD_TATESUGI=3/86400` は3件・86400秒として読み、明示した `_RESET` を優先する。
不正値は新規スレ立てをエラーとし、返信は受け付ける。管理画面からも不正値を保存できない。

## 保存・同時実行

`ThreadCreationRateLimit` が純粋な判定を担い、`PostingContext` と `ClientIdentity` で投稿情報を渡す。
予約・確定・取消と履歴の保持規則は集約 `ThreadCreationHistory` が持ち、Board DO はロック・ページの読み書き・
`ThreadCreationCodec` による変換だけを行う（AGENTS.md 3.5）。拒否はRPCで `ThreadCreationRejection` のコード
（例 `thread-creation:broad:network-group`）として返し、文言への変換は `PostingText` が行う。
通常の検証後、Thread DOがdatを保存する直前にBoard DOへ予約を依頼する。
Board DOは判定と履歴の追加を `blockConcurrencyWhile` で直列化する。
予約中の履歴は件数窓を進めず、期限内の予約との一致も別途拒否する。
これにより、後から失敗する他者の予約を使って古い履歴を窓外に押し出すことを防ぐ。

dat保存失敗時は予約を取り消す。dat保存後は確定し、その後の一覧・R2更新に失敗しても履歴は取り消さない。
確定RPCだけが失敗した場合は予約を残して一覧更新を続行し、作成済みスレッドの公開を妨げない。
DOをまたぐ処理のため、dat保存前後にプロセスが停止すると予約が残る場合がある。
予約の別枠照合は最長120秒（有効な規制のRESETがすべて短ければその最大秒数）とし、件数0の規制側RESETは含めない。
その間は海外全体やAS＋県のグループも保守的に制限する。期限切れの予約は確定履歴と同じ件数窓・RESETで扱い、別枠では制限しない。

Board DOに `threadCreationPageCount` と `threadCreationHistory:<ページ番号>` を追加する。
64件ごとに分割し、メタ情報とページ群を一括保存する。各照合値はソルト付きSHA-256で保存する。
既存のdat・log・settings・subjectListの形式、公開文字コード、ID・トリップ計算は変更しない。
保留予約を含む履歴8000件では新規予約を拒否し、ストレージの一括更新上限を超えないようにする。

導入前のスレ立て履歴は遡って取り込まず、導入後から記録する。
件数を増やしても既に切り捨てた古い履歴は復元しない。
AS全体対象リストの変更前後ではネットワークグループの値が変わるため、その軸は変更後に蓄積した履歴から適用される。
通常のIP・タイトルと広域のUAは引き続き照合する。

## 今後の検討

旧Scaladocに書かれていた構想。いずれも未実装で、認証（Lv）導入時に検討する。

- 端末情報（Lv9以下のみ）、未認証のASのみ・県のみ、認証済ID・未認証のセッションIDでの規制を追加する。未認証は海外からのスレ立てを禁止する。
- 同一UA・AS＋県の広域規制は、認証済み（L3以上）ならスルーする。
- 同一AS＋UAの組み合わせ（構想時点で将来廃止予定とされていたもの）。

## 管理画面・応答

管理画面の板設定（`/admin/boards/板名/`）の「スレ立て規制」で各設定とAS全体対象を編集する。
他の板設定・head.txtは保持する。その他の設定（直接編集）を含め、保存時に同じ検証を行う。
既存の管理認証・レスポンスヘッダーを引き継ぐ。
規制拒否はHTTP 200と `<!-- 2ch_X:error -->` を返し、datと公開スレ一覧を増やさない。

### Claude CLI

利用者の「claudeに依頼」という指示により、レビュー先をClaude CLIへ変更した。
秘密値・本番設定を除外した今回の差分と関連ソース・テストを渡し、ツールを無効にした読み取りレビューを依頼した。
初回レビューは完了。指摘の採否と対応方針は次のとおり。

| 指摘 | 判断・対応 |
| --- | --- |
| M-1: dat保存後に予約確定RPCが失敗すると一覧更新に進めず孤立する | 採用。確定失敗でも一覧更新を続行し、残留予約は保守的に扱う。障害注入テストを追加して成功。 |
| M-2: 残留予約が件数窓にかかわらず広域グループをRESET期間ブロックする | 採用。予約の別枠照合を最長120秒にし、その後は確定履歴と同じ件数窓へ入れる。件数0の規制側RESETは予約期間に含めない。 |
| L-1: 新規Board RPCのゲート内例外がDOリセットを引き起こす | 採用。Threadと同様にゲート内で捕捉し、外で失敗を返す。 |
| L-2: 履歴全ページを予約・確定ごとに読み書きする | 今回は変更しない。件数上限で有界、既定の1件では小さい。ページ単位の更新最適化は必要時に別途検討する。 |
| L-3: cancelが確定済み履歴まで消しうる | 防御的に採用。取消対象を同keyのpendingに限定する。現行の投稿経路からの到達例は確認されていない。 |
| L-4: 専用フォームのASN欄へ改行を入れると別設定行を注入できる | 採用。各入力のCR/LFを保存前に拒否。全5項目×3種類の改行による保存拒否、他設定とhead.txtの不変をテスト。実workerdでも確認した。 |
| L-5: 既存の不正設定は作成を拒否し、旧3/86400は旧値が有効になる | 意図した仕様として維持。新しい既定値で既存の明示設定を上書きしない。不正な設定は管理画面から修正できる。 |
| L-6: 設定不正時に内部設定名が出る | 今回は維持。SETTING.TXTの設定名は公開情報で、管理者が対象設定を特定できる。 |
| S-1〜3: IPv6はアドレス単位、生UAの一致、位置情報欠落時のグループなし | 指定された同一IP・同一UAと文書化済みの未知値の扱いを維持。/64への変更やUA判定の変更は今回行わない。 |

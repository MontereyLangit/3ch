# 07. v6 での ID の廃止

2026-09-26 ユーザー方針。v6（Step 5 以降）では、日付欄の **ID（`ID:xxxxxxxx`）を廃止**し、
投稿者の識別は名前欄末尾の**識別 ID**（`{国}.{県}.{市区町村} {回線}-{端末}`）に一本化する。

## 1. 理由

- v5 の段階で、自演の防止（見破り）の役割は ID ではなく識別 ID が果たしている。
  識別 ID は地域・回線・端末の組み合わせで、IP だけから作る ID より精度が高い。
- 両方を出すと、ID は識別 ID の下位互換の情報になり冗長である。
- v6 では識別 ID の端末部分を、**認証時のフィンガープリントから得た端末情報**で作る
  （v5 は UA と端末情報ヘッダ `x-ch3-device-information`。`01_現行v5の課題.md` 3 章の認証導入と対応）。

## 2. v5 の現状（参照）

| 項目 | v5 | 仕様書 |
| :-- | :-- | :-- |
| ID | `md5(IP + idGroup + dateSalt + salt)` → SHA-1 Base64 の先頭 8 文字。日付欄に `ID:xxxxxxxx` | 6.3 |
| 識別 ID | `{country}.{kenHash}.{cityHash} {asnHash}-{uaHash}`。名前欄末尾の `()` 内 | 6.4 |
| 周期 | どちらも `dateSalt`（`BBS_ID_RESET`、既定 86400 秒、JST 0 時基準）で日替わり | 6.3 |
| 板設定 | `BBS_ID`（`checked` / `ip` / `siberia` / `off`）、`BBS_ID_LV`、`BBS_ID_SHIKIBETSU` | 8.2 |
| スレタイ | ID がある板では、スレ立て時にタイトル末尾に ` [ID:xxxxxxxx★]` が付く | 6.3 |

**Step 3（Scala.js 移植）では ID をそのまま残す**（v5 とバイト単位で同一の出力を保つため。`AGENTS.md` §2 Step 3）。
廃止は新仕様化（Step 4 / 5）で行う。

## 3. 廃止に伴って決めること

- **専ブラの ID 機能との互換**: 専ブラの「ID 抽出」「ID で NG」「ID ごとの書き込み数表示」は、
  dat 第 3 フィールド（日付欄）の `ID:` を読んで動く。ID をなくすとこれらが効かなくなる。
  - 5ch の「ワッチョイ」も名前欄の識別子で、主要な専ブラは名前欄の正規表現 NG などで対応している。
    識別 ID だけでも自演の見破りと NG はできるが、**ID 抽出のポップアップ相当が使えなくなる**点は利用者への告知が要る。
  - 代替案: 日付欄に識別 ID 由来の値を `ID:` 形式で出す（中身は識別 ID のハッシュ）。この場合は「ID を廃止」ではなく
    「ID の中身を識別 ID に揃える」になる。どちらにするかは未決。
- **スレタイ末尾の ` [ID★]`**: 廃止する（識別 ID で置き換えるかは未決）。
- **板設定**: `BBS_ID` / `BBS_ID_LV` / `BBS_ID_GROUP` は廃止または識別 ID 側へ統合する。
  `BBS_ID_RESET`（日替わり周期）と `BBS_ID_GROUP`（計算のグループ）は識別 ID の計算にも使われているので、名前を変えて残す。
- **`siberia`（発信元 IP の直接表示）**: 識別 ID の `raw` 相当で足りるかを確認する。
- **ID 無しスレ（SETTING コマンド）**: 「識別 ID 無し」（`BBS_ID_SHIKIBETSU=d` 相当）に読み替える。
- **識別 ID の日替わり**: ID を廃止しても識別 ID は日替わりのまま（`dateSalt` を含む）とする想定。固定にすると追跡可能性が上がる。
- **過去ログ（Step 6）**: 既存の dat にある `ID:` はそのまま残す（過去の内容は書き換えない）。

## 4. 影響する他の検討

- `06_ActivityPub連携の検討.md` 3.2: 使い捨てアクターを「日替わり ID」ではなく「日替わりの識別 ID」から作る。
- 規制・自演検知（`01_現行v5の課題.md` 3・4 章）: 認証トークン単位の識別と、表示用の識別 ID は別物として持つ（識別 ID は表示・見破り用、規制は認証トークン単位）。

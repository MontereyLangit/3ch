## 3. 管理用 API

- Step 4 で**管理用の API を追加する**（2026-09-25 決定）。Next.js の管理画面はこの API を通して既存バックエンドを操作する。
- 条件は **DB を変えないこと**（DO / R2 / KV のキーとフォーマットはそのまま）。バックエンドへの API 追加自体は可。
- v5 / Scala.js 版にある HTML フォームの管理機能（`/admin/*`）は、新しい管理画面に置き換わった時点で廃止する。

## 4. スレの削除（モックの完全削除を含む）

**Step 4 で入れる**（2026-09-25 決定）。削除は、**外部（公開側）からは完全に見えなくするが、内部のデータは消さずに残す**操作とする
（2026-09-25 変更。当初案の「公開データを物理削除する」は撤回）。

| 対象 | 保存先 | 削除での扱い |
| :-- | :-- | :-- |
| dat（本文）・スレ設定・投稿者ログ・旧形式ログ原文 | Thread DO `dat` / `settings` / `log` / `legacyLog` | 残す。公開側には返さない |
| 旧形式の過去ログ本体 | R2 `{bbs}/thread/{key上位4桁}/{key}.cgi` | 残す。公開側には返さない |
| スレ一覧 | Board DO `subjectList` | 項目を外す |
| 過去ログ目次・ヘッドライン | R2 `{bbs}/thread/{kako}/subject.txt`, `headline.txt` | ファイルは書き換えない。配信時に除外する |

### v5 の「削除」との関係
v5 の削除（`Thread.moderate('delete')`、`thread.js:206-208`）は、すでにこの条件を満たしている。

- Thread DO に `hidden=true` を立てる → `getDat()` が空を返し、dat は 404 になる（`thread.js:32`, `main.js:173-`）。
- Board DO の `subjectList` から外し、`removed` に加える（`board.js:32-38`）。
- 過去ログ目次（`main.js:293, 311`）とヘッドライン（`main.js:148`）は、配信時に `removed` のスレを除外する。
- R2 の `.cgi` を直接返す公開ルートはない。
- データ（`dat` / `log` / `legacyLog` / `.cgi`）はどこも消していない。

したがって、**削除の中身は v5 の削除と同じ**でよい。DO / R2 のキーとフォーマットも変わらない。

### 決定事項
- **削除の操作記録はつけない**（2026-09-25 決定）。
- **削除系の操作はすべて確認モーダルを経由する**（2026-09-25 決定）。
  対象: スレ削除・レスのあぼーん・規制 / NG ワード / キャップの削除。

### 操作の一本化（2026-09-25 決定）
- モックの「完全削除」と v5 由来の「削除」は **1 つの操作にまとめる**。管理画面上の操作は「削除」1 つとし、中身は上記（v5 の削除と同じ）。

## 5. bbsmenu

- **手動編集は廃止し、boards テーブル（板マスタ）からシステム側で生成する方式に統一する**（2026-09-25 決定）。
  板休止（`01_現行v5の課題.md` 7 章、`02_板休止の検討.md`）の判定結果もこの生成に反映する。
- boards テーブルは Step 5 の DB 変更で作る。**Step 4 の間**の扱い:
  - 管理画面に bbsmenu 編集は出さない。
  - 生成は v5 の自動生成（`headline.txt` から列挙、`main.js:40-`）のままにする。
  - R2 に手動の `bbsmenu.html` が残っていると、自動生成より優先して返され続ける（`main.js:41-42`）。
    **バックエンドがこの R2 オブジェクトを参照しないようにする**（2026-09-25 決定）。R2 のオブジェクト自体は消さなくてよい。

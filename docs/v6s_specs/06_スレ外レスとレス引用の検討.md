# 06. スレに属さないレス（スレ外レス）とレス引用の検討

2026-09-25 検討開始。どのスレにも属さないレスを投稿できる機能と、それを支えるレス引用機能を検討する。
「スレ外レス」は本書での仮称で、UI 上の名前は未決（5 章）。

## 結論（案）

- **スレ外レス**: 板の新着レス一覧にだけ載るレス。一覧の最大表示件数から押し出されると、公開面からは消える。
  専門板の長期パートスレにそぐわない、すぐ消える雑なつぶやきの置き場にする。
- **レス引用**: スレ内レス・スレ外レスのどちらでも、スレ・板をまたいで引用できる（ふたばの引用と X の引用リポストの中間）。
  Web は専用ボタン、専ブラはレスの URL を本文に貼ることで引用する。**サーバーは本文中の 3ch のレス URL を検出して引用関係を記録する。**
- **引用されたスレ外レスは残る**: スレ外レスは「一覧から押し出され、かつ公開中のどのレスからも引用されていない」ときに消える。
  スレ内レスから引用されたスレ外レスは、そのスレ内レスが残る限り残り続ける。スレ外レス同士の会話は、最後の返信が一覧にある間は丸ごと残る（2.3）。
- **dat・Shift_JIS・専ブラ互換は変えない**: 引用はスレ内レスの本文中の URL として dat に入るだけで、サーバーが dat に引用元の本文を書き足すことはしない（3.2）。
- **消えるのは公開面だけ**: 投稿ログ（IP・UA など）は通常のレスと同じ保存期間で残す。開示請求への耐性のため（4.3）。
- **Step 5 以降の機能**: 新着レス一覧と引用関係の索引が要るので、v5 のストレージのままの Step 4 では出さない。

## 1. 経緯

| 世代 | 機能 | 内容 |
| :-- | :-- | :-- |
| v3 | 新着レスヘッドライン | sage でない新着レスの一覧。閲覧のみ |
| v4 | タイムライン | ヘッドラインをタイムラインに変えたもの。sage でない新着レスが載るうえ、**タイムライン自体にも投稿できた**。200 レスを超えた分は消えるので、タイムラインに直接書いたレスは過去ログに残らない。気軽なつぶやきを載せる「チラシの裏」として追加した |
| v5 | なし | 新着レス一覧自体がない（`01_現行v5の課題.md` 5 章）。全体ヘッドライン `headline.txt` は板ごとの最終書き込み 1 件（本文先頭 30 文字）だけ |
| **v6（本書）** | スレ外レス + レス引用 | v4 のタイムライン投稿に相当する機能を、有意義なレスを残す仕組み（引用）とセットで入れる |

### 狙い

- **専門板**は低頻度で長期間続くパートスレが多い（`04_dat落ちを採用しない.md`、`05_最大レス数の検討.md` 2.2 の AA スレは 11 年続いている）。
  そうしたスレに雑なつぶやきを書くと、スレの話題が散る・ログが薄まる。一方で、つぶやく場所がないと板に人が居着かない。
  スレ外レスは、スレを汚さずに板に「今いる人の気配」を出す手段になる。
- 方針企画書の「板単位のクリティカルマス」「専門板＝定着装置」に対し、専門板の平時の書き込みの敷居を下げる施策として位置づける。
- 新着レス一覧にはレス番がない。スレ外レス同士・スレ内レスとの会話を成り立たせるには、**レス番に代わる参照手段（引用）が必須**になる。

## 2. スレ外レス

### 2.1 基本仕様（案）

| 項目 | 案 | 備考 |
| :-- | :-- | :-- |
| 所属 | **板に属する**（どのスレにも属さない） | 板の規制・NG ワード・ID 設定・SETTING.TXT をそのまま適用するため。全体タイムライン直下のレスは作らない |
| 表示先 | 板の新着レス一覧（スレ内の age レスと時系列で混ぜる） | 全体の新着一覧に載せるかは未決（5 章） |
| 一覧の最大件数 | 板設定。既定は v4 と同じ 200 件を候補 | 一覧はスレ外レスとスレ内レスを合わせた件数で数える |
| 消滅 | 一覧から押し出され、かつ公開中のどのレスからも引用されていないとき（2.3） | 物理削除のタイミングは bg の定期処理でよい |
| sage | スレ外レスには sage の概念を持たない（常に一覧に載る） | メール欄は通常どおり保存・表示する |
| 名前・ID・トリップ・キャップ | スレ内レスと同じ計算 | v5 の ID は板（`BBS_ID_GROUP`）・日付・IP から計算し、スレキーに依存しない（仕様書 6.3）。同じ人のスレ内レスとスレ外レスで ID が一致する |
| 本文の長さ・行数 | 板設定をそのまま適用。スレ外レス用に短い上限を別に持つかは未決 | つぶやき用途なら短めでもよい |
| 画像・AA | スレ内レスと同じ扱い | |
| 識別子 | **板内の通し番号**（スレ外レス専用の連番）。レス番の代わりに引用・URL に使う | 3.1 |

### 2.2 投稿経路

| 経路 | 方法（案） |
| :-- | :-- |
| Web | 新着レス一覧の上部に投稿欄を置く |
| 専ブラ | `bbs.cgi` に**スレ外レス用の固定キー**（下記）を指定して投稿する。`subject.txt` に新着レス一覧を仮想スレとして 1 行載せ、専ブラから普通のスレとして開いて書き込めるようにする |

- 専ブラ向けの仮想スレは、**dat を毎回生成し直す読み取り専用のビュー**になる。一覧は先頭から押し出されていくので、
  追記専用ではなく、`Range` による差分取得の前提（取得済み部分が変わらない）を満たさない。
  - 専ブラは dat の縮小・不一致を「あぼーん検出」として全体を取り直すものが多い。その挙動に頼ることになるので、主要な専ブラでの動作確認が要る（5 章）。
  - 仮想スレのレス番はその時点の一覧内の順番にすぎず、安定しない。そのため仮想スレ内での `>>n` アンカーは使えず、会話は引用（URL）で行う。
  - 各行の本文末尾に、そのレスの固有 URL（スレ内レスなら元スレのレス URL、スレ外レスならスレ外レスの URL）を付けて配信する。
    専ブラ利用者はそれをコピーして引用に使う。
  - 仮想スレの 1 行目のタイトル・固定キーの値・`subject.txt` のどこに載せるか（先頭固定か、最終書き込み順か）は詳細設計で決める。
    固定キーは実在のスレキー（Unix 時刻）と衝突しない値にする。
- 仮想スレを `subject.txt` に載せない板設定も持てるようにする（専ブラで仮想スレが邪魔な板のため）。

### 2.3 消滅と保存の規則（案）

スレ外レスは、次の両方を満たしたときに公開面から消える。

1. 新着レス一覧から押し出されている。
2. **公開中の（消滅・削除されていない）どのレスからも引用されていない。**

この規則から、次の挙動になる。

| ケース | 結果 |
| :-- | :-- |
| 誰にも引用されないつぶやき | 一覧から押し出された時点で消える（v4 と同じ） |
| スレ内レスから引用された | スレ内レスは消えない（dat 落ちなし。`04_dat落ちを採用しない.md`）ので、**残り続ける**。「有意義なレスはスレに引用して残す」という使い方になる |
| スレ外レス同士の会話（A ← B ← C と引用が連なる） | 最後の返信 C が一覧にある間は、C が B を、B が A を引用しているので全部残る。C が押し出されると C が消え、続いて B、A の順に消える |
| 引用しているレスが削除された | 被引用がなくなれば、一覧外のスレ外レスは消える |

- 参照カウント方式なので、「残す」かどうかを運営者や投稿者が判断する必要がない（方針企画書「運営者が動かなくても死なない設計」）。
- 自分のスレ外レスを自分でスレに引用して残すことはできる。その場合でも残るのはスレ内レスの本文として公開される形なので、
  スレの住民の目に触れ、スレの容量（2 MB）も消費する。これを制限する必要はないと考える。
- スレ外レス同士で引用し合って延命させ続けることもできるが、延命させるには一覧に残る新しい投稿を続ける必要があり、通常の連投と同じ扱い（レート制限）で足りる。
- 消えたスレ外レスを引用していたレスでは、引用部分を「このレスは消えました」と表示する（削除との区別は 3.3）。

## 3. レス引用

### 3.1 引用の対象と URL

引用の対象は「固有 URL を持つレス」とし、URL を引用の識別子にする。

| 対象 | URL（案） | 備考 |
| :-- | :-- | :-- |
| スレ内レス | `/test/read.cgi/{bbs}/{key}/{n}` | 既存の read.cgi 形式。専ブラの「レスの URL をコピー」でこの形になるので、**専ブラからのスレまたぎ引用がそのまま成り立つ** |
| スレ外レス | 例: `/test/read.cgi/{bbs}/{固定キー}/t{通し番号}`、`/{bbs}/t/{通し番号}` など | 未決（5 章）。専ブラが URL をどう解釈するか（自前で開くかブラウザに渡すか）で選ぶ |

- 旧ドメイン（3chbbs.com）の URL や、`/test/read.cgi/{bbs}/{key}/{n}-{m}` のような範囲指定の扱いは詳細設計で決める。範囲指定は引用としては先頭レスだけを対象にする案が簡単。
- スレ内の `>>n` アンカーは従来どおり残す。引用は `>>n` を置き換えるものではなく、スレ・板をまたぐときと、スレ外レスを参照するときのための手段。

### 3.2 投稿時の処理

1. **引用の入力**
   - Web: 各レスの「引用」ボタンで投稿欄に引用先の URL を差し込む（本文中の URL として送る）。Web 版のフォームも専ブラと同じく本文中の URL で引用を表す。
   - 専ブラ: 利用者がレスの URL を本文に貼る。
2. **サーバーでの検出**: `bbs.cgi` の整形の後で本文中の 3ch のレス URL を抜き出し、引用先が実在する（削除・消滅していない）ものを引用関係として記録する。
   - 1 レスあたりの引用数に上限を設ける（例: 5 件）。超えた分は普通のリンクとして扱い、エラーにはしない。
   - 引用先が存在しない URL も、本文はそのまま通す（投稿を拒否しない）。
3. **dat への書き込み**: 本文は利用者が送ったとおり（URL を含む）で書き込む。**引用元の本文を dat に書き足さない。**
   - dat は先頭から追記するだけのファイルとして専ブラに差分取得される（`Range`）。後から引用元が削除されたときに dat の中の複製を消せない。
   - 引用元の本文を複製すると、削除依頼への対応が引用の数だけ広がり、スレの容量も消費する。
   - 専ブラでは URL がリンクになる。スレ内レスの URL は専ブラ自身が開ける。

### 3.3 表示

| 画面 | 表示（案） |
| :-- | :-- |
| Web（read.cgi・新着レス一覧） | 本文中の引用 URL を、引用先のカード（名前・日付・ID・本文の抜粋・所属スレ名）に展開する。X の引用リポストの表示に近い |
| Web の各レス | 被引用数と「このレスを引用しているレス」の一覧（スレ・板をまたいで）を表示する。ふたばの被引用表示に近い |
| 専ブラ（dat） | 本文中の URL のまま。展開はしない |
| スレ外レスの URL を直接開いた場合 | そのスレ外レス 1 件と、引用している／されているレスを表示する HTML ページ。消えた場合は 404 ではなく「消えました」ページを返す（410 相当。詳細設計で決める） |
| 引用先が削除された | 「このレスは削除されました」。消滅（2.3）とは文言を分ける |

- カードの展開は表示時に引用関係の索引から引く。引用先の本文を引用側に保存しない（3.2 と同じ理由）。
- 成人向け板を別ドメインに分ける場合（方針企画書「不可逆な設計判断チェックリスト」）、ドメインをまたぐ引用はカードに展開せず、リンクだけにする。

## 4. 実装面の検討

### 4.1 ストレージ（Step 5）

v5 のストレージ（KV 型 DO・R2 の `headline.txt`）には、新着レス一覧・スレ外レス・引用関係の置き場がない。
Step 5 のストレージ設計（`../v6/docs/feature/storage_basic_design.md`）に、次の 3 つを加える前提で検討する。

| データ | 置き場（案） | 理由 |
| :-- | :-- | :-- |
| スレ外レス本体（板内通し番号・本文・名前・ID など） | 板ごとの SQLite 型 DO（Board DO 相当）の表 | 通し番号の採番と一覧からの押し出しを、板ごとに直列化できる |
| 板の新着レス一覧 | 同上。スレ内レスは Thread DO から bg 経由で投入する | `01_現行v5の課題.md` 5 章「新着レス一覧は bg が投稿イベントを受けて索引を更新する」に合わせる |
| 引用関係（引用元レス → 引用先レス） | 板・スレをまたいで逆引きするので、D1 などの横断索引 | 被引用一覧・消滅判定（2.3）に使う |

- スレ外レスの投稿は、スレ内レスと違って Thread DO を通らない。投稿の同期処理は「板の DO への追記」だけにし、
  引用関係の索引の更新は bg で非同期に行う（`01_現行v5の課題.md` 1 章の方針と同じ）。
- 引用関係の索引は非同期なので、投稿直後の一瞬は被引用数が反映されない。消滅判定（2.3）は bg の定期処理で行い、
  索引の反映待ちで消してしまわないよう、一覧から押し出された後に猶予を置いてから判定する。

### 4.2 専ブラ互換（`AGENTS.md` §3.4）

| 不変条件 | 本機能での扱い |
| :-- | :-- |
| dat の 5 フィールド構造・本文前後の半角スペース | 通常のスレの dat は変えない。仮想スレの dat も同じ形式で出す |
| エラー時も HTTP 200 + `<!-- 2ch_X:error -->` | スレ外レス投稿のエラーも同じ形式で返す |
| `Range` / `304` | 通常のスレは変えない。仮想スレは差分取得が成り立たない（2.2）。仮想スレに対する `Range` 要求にどう応えるか（常に全体を返す、`416` を返すなど）は実機確認のうえで決める |
| Shift_JIS 出力 | 仮想スレの dat・`subject.txt` も Shift_JIS |

### 4.3 モデレーション・法務

- **公開面から消えても投稿ログは消さない。** IP・UA などのログ（仕様書の `log` 相当）はスレ内レスと同じ保存期間で持つ。
  スレ外レスは公開面に残らないため、誹謗中傷・犯行予告などが「消えたので証拠がない」状態になりやすい。開示請求・削除要請への対応（KSF 6）のため、ログの保存は通常のレスと同じにする。
- 規制（`deny.cgi` 相当）・NG ワード・レート制限はスレ内レスと同じ判定を通す。スレ外レスは立てる手間がなく流れも早いので、
  荒らし・スクリプトの標的になりやすい。レート制限はスレ内レスと別枠にするか、合算にするかを決める（5 章）。
- 削除はスレ外レスでも通常のレスと同じく管理画面から行う。削除すると引用関係が外れ、2.3 の規則で連鎖的に消えるものが出る。
- 避難モード（方針企画書）時に、スレ外レスが新着レス一覧を埋め尽くして一覧が役に立たなくなることが考えられる。
  板設定でスレ外レスを止められるようにする（既定は有効）。

## 5. 未決事項

- UI 上の名前（「つぶやき」「チラ裏」「ひとこと」など）。
- 全体の新着レス一覧（全板横断）にスレ外レスを載せるか。載せると専門板の外にも見えて流入になる一方、つぶやきが全体に流れる。
- 一覧の最大件数の既定値（v4 の 200 を候補）と、スレ外レスの本文の上限を別に持つか。
- スレ外レスの URL の形式（3.1）。主要な専ブラ（ChMate、JaneStyle、Siki など）が、非数値のキーやレス番を含む read.cgi 形式の URL をどう扱うかを実機で確認して決める。
- 専ブラ向け仮想スレ（2.2）が主要な専ブラで実用になるか（あぼーん検出での取り直し、`Range` 要求への応答）。実用にならない場合、専ブラからはスレ外レスを「投稿できるが一覧は Web で見る」扱いにする。
- 1 レスあたりの引用数の上限。
- スレ外レスのレート制限を、スレ内レスと別枠にするか合算にするか。
- 消えたスレ外レスの URL に返すステータス（404 / 410）と表示。
- 引用 URL の検出対象に、旧ドメイン（3chbbs.com）や将来の別ドメイン（成人向け板）を含めるか。

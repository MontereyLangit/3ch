# 05. スレの最大レス数（1000 → 2000）の検討

2026-09-25 検討。一部の 2ch 型掲示板で採用例のある「最大 2000 レス」を、
Durable Objects の制約と dat 配信の性能から検討する。
ストレージは `../v6/docs/feature/storage_basic_design.md` / `thread_lifecycle_basic_design.md`（以下 v6 設計）をベースにする。

## 結論（案）

- **最大レス数は板ごとの設定にし、既定は 1000 のまま。専門板は 2000 を既定にする。**
  v6 設計はすでに板設定 `MAX_RES`（既定 1000、上限クリップなし）を持っているので、仕組みの追加は要らない。
  v3 も `MAX_RES` を 300〜2000 の範囲で板ごとに設定できた。
- **dat の容量上限は、レス数に関係なく DO の制約から決める。512 KB はやめる**（2026-09-25 ユーザー判断）。
  512 KB には DO 上の根拠がない（旧 2ch の慣習値と考えられる）。512 KB のままだと、2000 レスの板では伸びたスレの
  1 割程度が 2000 に届く前に止まる（下記 2 章）。
  - 容量上限は「通常のスレでは到達せず、AA・連投荒らしなどの異常なスレだけを止める安全弁」と位置づける。
  - **全板固定で 2 MB とする**（2026-09-26 決定。下記 2.1・2.2。当初 1 MB としたが、AA スレの実測で 2 MB に変更）。
- **Step 4（v5 のストレージのまま）では 2000 にできない。** 1000 レスでも KV 型 DO の 1 値の上限に当たりうる（KB-28）。

## 1. 実データ（過去ログ）

`kako-data/dat` のうち、950 レス以上のスレ 1,420 本の dat サイズ（Shift_JIS）:

| | 1000 レス前後のスレ | 2000 レスにした場合の推定（2 倍） |
| :-- | :-- | :-- |
| 中央値 | 125 KB | 約 250 KB |
| 90 パーセンタイル | 261 KB | 約 520 KB |
| 99 パーセンタイル | 493 KB | 約 990 KB |
| 最大 | 5.9 MB（AA・連投などの外れ値） | — |

## 2. Durable Objects の制約

v6 設計（SQLite 型 DO、レス 1 件 = `posts` 1 行 + `post_log` 1 行、配信はメモリ上の Shift_JIS バッファ）での影響:

| 制約 | 1000 レス | 2000 レス | 判定 |
| :-- | :-- | :-- | :-- |
| DO の保存容量（10 GB / DO） | 数百 KB | 1 MB 前後 | 問題なし |
| 1 行の上限（キー + 値で 2 MB） | レス 1 件ごとの行なので無関係 | 同左 | 問題なし |
| 書き込みコスト（行書き込み $1.00 / 100 万行） | 1 レスあたり 2 行 | 同左（総額はレス数に比例するだけ） | 問題なし |
| 起動時の読み込み（ハイドレーション） | 1,000 行 | 2,000 行（行読み取りの課金は無視できる額、時間も数十 ms 程度） | 問題なし |
| メモリ（isolate あたり 128 MB を複数の DO で共有） | バッファは dat の 1.5〜2 倍 | 同左 | 容量上限を決める唯一の制約（2.1） |
| **dat の容量上限（v6 設計 512 KB）** | 99 パーセンタイルでも収まる | **90 パーセンタイル付近で到達** | **要変更**（2.1） |

### 2.1 容量上限を DO の制約から決める

v6 設計で、dat の大きさに効いてくる DO の制約は**メモリだけ**である。

- 保存は 1 レス 1 行なので、1 行の上限（2 MB）にも DO の容量（10 GB）にも、スレの大きさは効かない。
- メモリは isolate あたり 128 MB で、同じ isolate で動く複数の DO が共有する。
  v6 設計は配信用に dat 全体の Shift_JIS バッファ（dat の 1.5〜2 倍を確保）をメモリに常駐させる。
- 2 MB のスレでバッファは最大 4 MB。同じ isolate に大きなスレが数本重なっても 128 MB に収まる。
  - 1000 レスの板: 99 パーセンタイル 493 KB で、通常のスレは十分収まる。AA スレも 1000 レスまで収まる（2.2）。
  - 2000 レスの板: 99 パーセンタイルが約 990 KB（1000 レスの実測の 2 倍で推定）で、通常のスレは収まる。
- 板ごとに容量上限を変える方式（既定 1 MB・AA 板だけ 2 MB など）はとらない。どの板を AA 向けにするかを運営者が判断し続ける必要があり、
  方針企画書の「運営者が動かなくても死なない設計」に反する。
- 荒らし対策としては 1 MB と 2 MB で大差ない（1 件 16 KB の連投なら 60 件か 120 件かの違い）。荒らしを止める本命はレート制限と認証で、
  容量上限は最後の安全弁にすぎない。
- 実データの最大（5.9 MB）は、ID を 1 件ごとに変えるスクリプト荒らしが 1 件約 16.5 KB の数値文字参照（NCR）のレスを
  17 分間で 338 件投稿したスレ（`livegalileo/1663271703`、2022-09-16）。2 MB で止まる側に入る。
  1 MB（1,048,576 B）を超える過去ログは全 30,574 本中 9 本。中身を確認した 6 本はすべて荒らし（NCR 連投、AA タグに無意味な文字列や
  小説本文を入れた連投）だった。1 MB 弱では、`!SETTING` で本文上限を 8192 に上げた長文連投のスレ（1,000 KB 弱）もある。残る 3 本は 7,966〜10,000 行の超長スレで、中身は未確認。
  一方、荒らしのない通常の雑談スレでも 1 MB 近くになる例がある（`livegalileo/1657530475`「なんG遊牧民・避難民雑談スレ」、927 レスで 994 KB）。

### 2.2 AA スレの実測

5ch AA 板の虐殺系 AA スレ（`mona/1443094604`）の dat を実測した（Shift_JIS）。

| 項目 | 値 |
| :-- | :-- |
| レス数 | 957 |
| 期間 | 2015-09-24 〜 2026-08-21（約 11 年。継続中） |
| 全体サイズ | 950 KB |
| 1 レスのサイズ | 中央値 813 B / 90 パーセンタイル 2.2 KB / 最大 4.1 KB |
| gzip 圧縮後 | 161 KB（約 1/6） |

- 512 KB（v6 設計の現行値）では 589 レス目で止まる。
- 3ch では `'` が `&apos;`（6 バイト）にエスケープされる（`bbs.cgi.js:275`。5ch はそのまま）。この dat には `'` が 6,779 個あり、
  3ch で保存すると約 34 KB 増えて約 984 KB になる。1000 レス換算で約 1.03 MB となり、**1 MB では 1000 レスの手前で止まる**。
- 2 MB なら 1000 レスまで余裕をもって収まる（2000 レスの板でこのペースだと約 2 MB で、上限付近）。
- 低頻度で長期間続くスレの典型でもあり、dat 落ちを採用しない方針（`04_dat落ちを採用しない.md`）の実例でもある。

v6 設計が 512 KB の理由に挙げている「専ブラの取得・表示が破綻する」は、今の専ブラと回線では数 MB でも当たらないと考える。
ただし実機での確認は要る（5 章）。

v5（KV 型 DO、1 スレの dat を 1 値で保存）では、1 値の上限 128 KiB に対し、
1000 レスのスレの中央値がすでに 125 KB（Shift_JIS）ある。V8 のシリアライズでは日本語が 1 文字 2 バイトになるため、
**v5 では 1000 レスでも上限に当たりうる**（KB-28）。2000 は Step 5 のストレージ移行が前提。

## 3. dat 配信の性能

| 観点 | 影響 |
| :-- | :-- |
| 専ブラの差分取得（`Range`） | 取得済みの続きだけを取るので、最大レス数を増やしても 1 回あたりの転送量は変わらない |
| 専ブラの初回取得・再取得 | 全体を取る。2000 レスで中央値約 250 KB、最大でも容量上限の 2 MB。gzip が効けば AA スレでも約 1/6（2 MB で 350 KB 前後） |
| サーバー側の配信 | v6 設計はメモリ上の Shift_JIS 済みバッファを返すだけなので、サイズに比例するのはコピーと転送のみ。変換のやり直しはない |
| Web 版（Step 4、SSR） | 2000 レスを 1 ページで描画すると重い。「最新 50」「100 件ずつ」などの分割表示を既定にする |
| 専ブラの互換性 | 1000 超えのストッパーレス（`1001` / `Over 1000 Thread`）は v6 設計で最大レス数に合わせて可変になっている（`2001` / `Over 2000 Thread`）。v3 で 2000 を運用していた実績はあるが、主要な専ブラでの動作は実機で確認する |

## 4. 運用・方針企画書との関係

- 最大レス数を増やすと、次スレを立てる頻度が半分になる。
  - 専門板（低頻度で長く続く）では、次スレを立てる手間が減り、スレが続きやすい。方針企画書の「専門板＝定着装置」に合う。
  - 総合板・実況系（高速で流れる）では、スレが重くなるだけで利点が少ない。1000 で区切る文化もある。
- そのため、全板一律ではなく、**板の性格ごとに変える**のがよい。v6 設計の専門板プリセット（`SettingTxtPreset.specialized`）は
  今 `MAX_RES=1000` を出力しているので、これを 2000 に変える。

## 5. 未決事項

- v6 設計の `ThreadCapacity.MAX_DAT_BYTES`（512 KB）を 2 MB に変え、容量ストッパーレスの文言（`512KB` / `Over 512 Thread`）をどう変えるか決める。
- 本文の長さを NCR 展開後の実バイト数で数えているか（v5 / v6 設計とも未確認）。上記の荒らしは NCR で 1 文字 7〜8 バイトに膨らませていた。
- 主要な専ブラ（ChMate、JaneStyle、Siki など）での 2000 レス・1〜2 MB のスレの表示の重さの確認。
- v5 / v6 で dat・subject.txt が実際に gzip で配信されているかの確認（Cloudflare の自動圧縮が効いているか。`Range` / 206 応答での扱いも含む）。
- `!extend` でスレ単位に最大レス数を上げられる上限（板設定を超えてよいか）。

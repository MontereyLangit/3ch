## セルフレビュー

| 指摘・確認事項 | 判断・対応 |
| --- | --- |
| export の moduleID の分離だけではサーバ実装が client に混入する | client を独立した `bbsClient` でリンクし、`bbs` から client ソースの取り込みを削除。 |
| 単一プロジェクトを前提とするコメントが残る | Vite・sbt・ClientEntry のコメントを現構成に合わせて更新。 |
| 再発時に Scala の機能テストだけでは検出できない | static 配下の全 JS を検査する KB-27 回帰テストを追加。識別子・文字列の検査であり、あらゆるコード漏えいの完全な証明ではない。 |
| 公開プロトコル・ストレージ・認証への影響 | サーバソースを変更せず、Scala.js のリンク対象だけを分離。 |
| 全体テストで管理 POST の Origin 検証が失敗 | 利用者から意図的な削除との確認とテスト修正指示を受けた。Origin / Fetch Metadata によらず認証済み POST を受け付ける期待値へ更新し、保存結果も検証。仕様書を現仕様に合わせて訂正。 |

## 検証

- `npm run v6:build`: 成功。client の Vite 表示時間 11.39 秒、server 14.61 秒（起動・コンパイル・リンク込み。変更前との比較測定ではない）。
- `dist/static/client.js`: 358,907 → 11,444 bytes。サーバ専用マーカーの残存なし。
- `npm run v6:typecheck`: 成功。
- `npm test`: 2 件成功（実 workerd 統合テスト、KB-27 回帰テスト）。不正レス番号・移動先 key 重複の拒否テストで想定されたエラーログが出るが、アサーションは成功。
- `sbt test`: common JVM 10 件、common JS 10 件、bbsClient 1 件、bbs 132 件、すべて成功。
- sbt 起動時に Java 25 と sbt ランチャー由来の既存 Unsafe 警告あり。抑制していない。

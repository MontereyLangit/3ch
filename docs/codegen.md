# codegen（`@route` / `@islands` の配線生成と DO の型）

`@route` / `@islands` から HonoX の route / island ファイルと SSR 用の Scala API（`IslandComponents`）を作る仕組みは、
独立フレームワーク hx4s の `sbt-hx4s`（`Hx4sPlugin`）と `hx4s-codegen` が持つ。宣言の規則・拒否する誤り・出力の規則・エラーの形式・
設定キーは hx4s の文書を参照する（hx4s の checkout の `docs/hx4s/codegen.md`、`docs/hx4s/build-integration.md` 2.2・3.3）。
3ch の `codegen/` プロジェクトに残るのは DO の TS 型と RPC スタブの生成（`GenerateDurableObject*`）だけで、`docs/durable-object-stubs.md` を参照。

## 生成物と実行のきっかけ

| 生成物 | きっかけ | 備考 |
| --- | --- | --- |
| `app/routes/**/*.ts`, `app/islands/**/*.tsx` | `npm run v6:generate`（`sbt bbs/hx4sGenerate codegen/run`） | Git 管理する。内容が同じなら書き直さない |
| `app/scalajs-durable-objects.generated.d.ts` | 同上（`codegen/run` = `GenerateDurableObjectTypesMain`） | DO の TS 型 |
| `bbs/target/scala-3.3.8/src_managed/main/io/_3ch/bbs/generated/IslandComponents.scala` | bbs のコンパイル（`Hx4sPlugin` が `Compile / sourceGenerators` に登録） | クリーンな checkout でも `sbt test` だけで通る |
| `.../io/_3ch/bbs/external/cloudflare/DurableObjectStubs.scala`（src_managed） | bbs のコンパイル（`generateDurableObjectStubs`） | DO の RPC スタブ |

## 3ch の設定（`build.sbt` の `bbs`）

| キー | 値 | 理由 |
| --- | --- | --- |
| `hx4sClientProject` | `bbsClient` | |
| `hx4sServerSources` / `hx4sClientSources` | `bbs/.../Main.scala` / `bbs-client/.../Main.scala` だけ | 下記 |
| `hx4sIslandComponentsPackage` | `io._3ch.bbs.generated` | 既存の import を変えない |
| `hx4sGeneratedMarker` | `// This file is generated by codegen` | hx4s 移行前の生成ファイルと同じマーカー。違うと既存の生成ファイルを手書きとみなして上書きしない |
| `hx4sBanner` | 3 行（生成元・手で編集しない・ソース） | 1 行目はマーカーで始める |
| moduleID・出力先・接頭辞 | hx4s の既定（`server` / `client`、`app/routes`・`app/islands`、`scalajs:`） | |

走査するソースを全ソース（hx4s の既定）にせず 2 つの `Main.scala` に絞るのは、3ch では `@route` / `@islands` を
`Main` にだけ書く約束で、宣言の場所を 1 か所に保つため。codegen は構文だけを読むので、全ソースを渡すと bbs の数百ファイルを毎回解析し、
`IslandComponents` の増分判定（client のソースの内容がキー）も bbs-client のどのファイルを変えても生成し直しになる。
`Main` 以外に宣言を書いても生成されないので、宣言は `Main` に置くこと。

client の export は `hx4s.react.IslandExport[P]` の型で宣言する（props の無い `AuthModalJs` を除く）。
`@islands[P]` の `P` と宣言型の照合は hx4s-codegen が、宣言型と描画関数の型の照合は Scala のコンパイラが行う。
props の検証は `IslandExport.apply` に渡す各 props の companion の `fields` で行う（`docs/islands-ssr.md`）。

`bbs/hx4sCheckDependencies`（`hx4sGenerate` と IslandComponents の生成が先に呼ぶ）は、bbsClient が bbs に、bbs が bbsClient に
classpath で依存していないことを確かめる。
